פיענוח קלט וסינטקס (Parsing) Regex גלובלי נאיבי שסרק את כל המסמך וגרם ל"גניבת" שורות גוף לסעיפי מטא-דאטה; שימוש ב-indexOf לחיתוך הערות. DFA AST Parser: סריקה דטרמיניסטית מבודדת פתיח (Header Prelude), עם סורק סוגריים מאוזן רקורסיבי (Balanced Scanner) להערות מקוננות.

אלגוריתם שבירת שורות First-Fit חמדן ומקומי. נטייה לשבירת מילים אחרי גרשיים (ע"כ) ולרווחים לא אחידים. Hebrew Knuth-Plass (Total-Fit): מודל Box-Glue-Penalty עם קנס כבד על שבירת ראשי תיבות (+5000), הגנת מקף, וחלון מילה ראשונה מחושב.
איזון טורים וסופי פרקים לולאת חיפוש מקומית ב-DOM ומתיחה מלאכותית של line-height עד 1.8x בטור הבודד, שהרסה את רשת השורות. Multi-Column Dynamic Programming: אופטימיזציה גלובלית המאזנת לפי שורות שלמות, נועלת את ה-Baseline Grid, ומאזנת מושלם סופי פרקים.
תקציב הערות שוליים (Footnotes) חישוב חמדן בדיעבד. סכנה מתמדת של גלישת הערות מעבר לגבולות דף A4 בעת הדפסה. שריון תקציב גובה מתמטי מראש בתוך פונקציית העלות של ה-DP, המבטיח 100% תאימות לגבול הדף.
עריכה חיה בעורך (Live Sync) דריסת סמן הכתיבה (Caret Focus) בכל 350ms עקב קריאת editor.innerHTML = '' ב-updateEditorWithPageBreaks. שימור סמן מדויק (Caret Preservation): חישוב היסט התווים היחסי ושחזור מלא של הסמן והפוקוס תוך כדי הקלדה רציפה.

מקרי קצה מורכבים, כשלי V1 ומדריך התיקון ההנדסי

להלן ניתוח שורש הבעיה (Root Cause) עבור 4 הכשלים החמורים ביותר של הגרסה המקורית וכיצד הם נפתרו הנדסית בגרסת Master V2:

1. סטיית מספרי עמודים בתוכן העניינים (TOC Desynchronization on Odd Page Break)

שורש הכשל ב-V1: ב-typesetter.js:1848, הקוד רשם: headingPageMap[h2Id] = toGematria(pageIndex); לפני הקריאה ל-ensureOddPageStart(). אם העמוד היה זוגי, נוצר עמוד ריק ו-pageIndex גדל ב-1, כך שה-TOC הפנה לדף הריק! בנוסף, נעשה שימוש ב-toGematria פשוט במקום ב-formatPageNumberDisplay, מה שדרס את המספור של כרכים מאוחרים (כרך ב').

התיקון ההנדסי ב-V2: רישום מספר העמוד מתבצע אך ורק לאחר סיום כל בדיקות האי-זוגיות והזרקת הדפים החלקים, ונעשה שימוש ישיר בפונקציית הפורמט המלאה:

// תיקון ב-V2 (typesetter.js):
const { displayPageNum } = formatPageNumberDisplay(pageIndex);
headingPageMap[block.id] = displayPageNum || toGematria(pageIndex);
pageIndex++;

2. השמטת שורות שקטה בקריסת bestFitLine === 0

שורש הכשל ב-V1: ב-typesetter.js:2037, כאשר פסקה לא נכנסה בטור, הקוד קרא ל-targetCol.removeChild(pElem). לאחר מכן, אם הטור היה ריק (!pageHasContent), הקוד קבע bestFitLine = 1 ועדכן את האלמנט המנותק מבלי להחזירו לעץ ה-DOM! השורה הראשונה נעלמה לנצח.

התיקון ההנדסי ב-V2: כל הלוגיקה החמדנית של bestFitLine הוחלפה ב-MultiColumnPageBalancer מבוסס תכנון דינמי (DP), המבטיח שלמות נתונים מתמטית — שורות אינן מנותקות מה-DOM לעולם.

3. חיתוך שגוי של הערות שוליים בעלות סוגריים מקוננים

שורש הכשל ב-V1: שימוש ב-text.indexOf(closeDelim) גרם לכך שהסוגר הסוגר הפנימי הראשון בהערה כגון [ראו רמב"ם [הל' שבת] שביאר] סגר את ההערה בטרם עת, ושארית ההערה נפלטה כטקסט משובש לתוך גוף הספר.

התיקון ההנדסי ב-V2: הוטמע מנגנון Balanced Bracket Scanner בתוך מחלקת ToraniASTParser:

// סריקה מאוזנת מובנית ב-ToraniASTParser (typesetter.js):
while (cur < text.length && depth > 0) {
    if (text.startsWith(this.fnOpen, cur)) { depth++; cur += oLen; }
    else if (text.startsWith(this.fnClose, cur)) { depth--; cur += cLen; }
    else { cur++; }
}

4. דריסת סמן הכתיבה (Caret Obliteration) בעורך הטקסט בעת עריכה חיה

שורש הכשל ב-V1: הפונקציה updateEditorWithPageBreaks קראה ל-renderEditorContent שביצעה editor.innerHTML = '' בכל 350ms, והשמידה את אובייקט ה-Selection של הדפדפן בזמן שהמשתמש מקליד.

התיקון ההנדסי ב-V2: הוטמע מנגנון שימור סמן מלא ב-app.js המחשב היסט תווים ומשחזר אותו בדיוק מוחלט:

// שימור סמן מלא ב-app.js:
const hasFocus = (document.activeElement === editor);
const savedOffset = hasFocus ? getCaretCharacterOffsetWithin(editor) : -1;
renderEditorContent(clean, pageBreaks);
if (hasFocus && savedOffset >= 0) {
    setCaretPosition(editor, savedOffset);
}

גישות אלגוריתמיות חלופיות והערכה הנדסית

4.1 ניתוח סיבוכיות מתמטית וביצועים

במערכת DTP תורנית, מנוע העימוד מתמודד עם שלוש רמות של מורכבות:

  • רמת הקלט (Lexing/Parsing): הפיכת טקסט גולמי לרצף טוקנים. ב-V1 נעשה שימוש ב-Regex כבד בכל מחזור ($O(N \cdot M)$ עם סיכון לדליפת מטא-דאטה). ב-V2 פועל אוטומט סופי דטרמיניסטי (DFA) הסורק את הטקסט במעבר יחיד בסיבוכיות לינארית $O(N)$.
  • רמת המיקרו-טיפוגרפיה (Line Breaking): ב-V1 הפירוק לשורות דרש הזרקת תגיות span ומדידת DOM, שגרמה לסיבוכיות של עשרות אלפי Reflows. ב-V2 אלגוריתם Knuth-Plass פועל כ-Forward DP על גבי מטמון Canvas בסיבוכיות $O(W \cdot K)$ (כאשר $W$ מספר המילים ו-$K$ עומק החלון), ללא שום קריאת DOM.
  • רמת המאקרו-עימוד (Column & Page Balancing): ב-V1 נעשה ניסיון מקומי חמדן ליישר טורים ע"י מתיחת שורות ששברה את ה-Baseline Grid. ב-V2 אלגוריתם ה-DP סורק את מרחב החלוקות האפשרי בעמוד ($R \times L$) וממזער את פונקציית הקנס הריבועית תוך נעילת רשת שורות קשיחה.
