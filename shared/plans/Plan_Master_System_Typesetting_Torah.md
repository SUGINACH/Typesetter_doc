## מבוא והגדרת חזון המערכת

מטרת העל של הפרויקט היא יצירת **מערכת עימוד מקצועית בקוד פתוח (Web-based Open Source DTP)** לספרות תורנית ועיונית מורכבת על גבי דפי A4. המערכת נועדה להציג אלטרנטיבה עדיפה על תוכנות ותיקות ונוקשות כמו "תג" (Tag) ומערכי סקריפטים מסורבלים באינדיזיין (InDesign):
1. **עליונות אלגוריתמית:** ניהול עצמאי ואוטומטי של שכבות טקסט מרובות (כותרת רוחבית, טורים מקבילים, הערות שוליים, הערות סיום והערות צד).
2. **נגישות וקלות שימוש:** ממשק עריכה ויזואלי אינטואיטיבי (WYSIWYG) לצד יכולות שליטה טיפוגרפיות כירורגיות, ללא צורך בכתיבת קודי סדר עתיקים או רכישת עשרות תוספים חיצוניים.
3. **אפס תלויות שרת:** פריסה מלאה בצד לקוח (Client-Side HTML5/CSS/JavaScript), עם תמיכה מלאה בהדפסה ישירה וייצוא דפוס מושלם ל-PDF.

### 1. ממשק המשתמש, עורך הטקסט ובקרת האירועים
* **סרגל צד תלת-חלוני מתכוונן:** מסך העבודה מחולק לשלושה אזורים עיקריים — מימין אזור הדבקה ועריכת תוכן בממדים מלאים; במרכז לוח הגדרות מתקפל לרצועת שליטה ברוחב מותאם עם מנגנון אקורדיון; ומשמאל משטח תצוגה מקדימה של דפי A4. פס גרירה ייעודי מאפשר הרחבה והתאמה אישית של רוחב העבודה בין 340 ל-950 פיקסלים.
* **עורך טקסט מבוסס חוצצי עמודים דינמיים:** הטקסט מוצג בתיבת עריכה עשירה שבה מוזרקים חוצצי עמודים ויזואליים הנושאים את מספר העמוד והגימטריה שלו. חוצצים אלו מעוגנים כרכיבים שאינם ניתנים לעריכה, ומוסרים אוטומטית בעת העתקת טקסט כדי לשמור על טקסט גולמי נקי.
* **סנכרון גלילה ומיקוד דו-כיווני:** לחיצה על עמוד כלשהו בתצוגה המקדימה מקפיצה ומדגישה מיידית את השורה התואמת בעורך הטקסט. במקביל, הזזת הסמן בעורך הטקסט גוללת ברכות את התצוגה המקדימה לעמוד המעומד שבו נמצאת השורה.
* **זום A4 אוטומטי חסין עיוותים:** התצוגה המקדימה מתאימה את קנה המידה שלה באופן רספונסיבי למרחב החלון הפנוי תוך שימוש במנגנון שינוי מידות וקטורי, המונע טשטוש של אותיות וקטוריות ומתאפס בהדפסה ישירה לגודל דף טבעי ומדויק של 210 על 297 מ"מ.
* **כוונון אינטראקטיבי של תיבות שער:** מצב עריכה גרפי מאפשר למשתמש לתפוס ולגרור בעזרת העכבר את תיבות הטקסט על גבי השערים, לשנות את מידותיהן משמונה נקודות אחיזה, ולשמור את הקואורדינטות המדויקות במ"מ בנפרד עבור כל שער ושער.
* **מנגנון חציצת שינויים:** המערכת מפרידה בין עדכוני צבע ומראה קלים (החלים מיידית) לבין עדכוני עימוד כבדים של כלל הספר. שינויים כבדים מפעילים חיווי פעימה זהוב בראש הסרגל ("עדכן ועמד מחדש"), ומונעים את תקיעת הדפדפן בעת הקלדה או גרירת סליידרים.

### 2. מאגר העיטורים, השערים והגרפיקה הווקטורית
* **שערי ספר מודולריים:** המערכת כוללת שלושה סוגי שערים — שער ראשי רחב, שער אחורי מודולרי המחולק לארבעה מקטעים נפרדים (שמירת זכויות, הוצאה לאור, פרטי קשר, פרטים נוספים), ושערי משנה לחלקי הספר המבצעים פיצול אוטומטי בין כותרת ראשית לתת-כותרת.
* **מערך עיטורים נרחב:** עיטורי רומח, שושנתא, מעויינים וסלסולים תורניים. העיטורים תומכים בהיפוך אנכי ואופקי, התאמת רוחב מדויקת לרוחב הטקסט של כותרת 2, והגבלת גובה עצמאית בעיטורי צד של כותרת 3.
* **קווי הפרדה להערות שוליים:** שליטה במפרידים מעוצבים — קו שלם, קו שליש ימני (נוסח דפוס וילנא), קו חצי מרכזי, קו כפול, וקווים המשלבים גליפים דקורטיביים של כוכביות, ניצוצות ויהלומים.
* **מנהל ערכות נושא חיצוניות וסורק תיקיות מקומי:** תמיכה בטעינת קובצי הגדרות ב-JSON וסריקת תיקיות נכסים מקומיות, הממיינת אוטומטית קובצי איור לספריות העיטורים והשערים הרלוונטיות ומציגה אותם בבורר כרטיסיות חזותי.

### 3. מנוע העימוד, שבירת השורות, האיזון והפאגינציה
* **סורק מטא-דאטה וטוקנייזר היררכי:** חילוץ מטא-דאטה משורות הפתיחה של המסמך, זיהוי כותרות לפי קידומות מוגדרות (מרמה 0 עד רמה 7), וזיהוי הערות שוליים וסיום לפי תוחמים מובנים (סוגריים מרובעים או קידומת ייעודית).
* **מדידת שורות אטומית ב-DOM:** פירוק פסקאות לשורות מעומדות אמיתיות באמצעות בדיקת מיקומי גובה פיזיים של מילים בתיבת מדידה מכוילת, תוך הגנה על סוגרי הערות שוליים ומניעת שבירתם באמצע מילה.
* **שליטה בשורות יתומות ואלמנות:** דחיית שורות בודדות בראש טור או בסופו, ומניעת כותרות יתומות שאינן מלוות בלפחות שתי שורות טקסט של הפסקה הבאה.
* **מנוע איזון טורים דו-שלבי:** בסופי פרקים ולפני כותרות רוחביות (הנפרסות כטור בודד במרכז העמוד), המערכת סורקת את כל נקודות החיתוך האפשריות ומאזנת את גובה הטור הימני והשמאלי, תוך הבטחה מוחלטת ששני הטורים לא יחרגו מתקציב הגובה הפנוי של העמוד.
* **יישור אנכי מדורג ב-5 רמות:** סגירת פערי גובה שיוריים בין טורים בעזרת הגדלת מרווחים לפני כותרות, אחרי כותרות, בין פסקאות, בין שורות, וברווחי מילים בטור הקצר.
* **מחולל דוחות דיאגנוסטיקה:** כפתור צף בכל עמוד מאפשר להוריד קובץ דו"ח מפורט הכולל צילום חי של העמוד, פירוט מלא של כל רכיבי ה-DOM, פערי גובה, ואזהרות אוטומטיות על חריגות או חפיפות.

### 4. שלד התצוגה והגדרות העיצוב
* **רשת העמוד (Grid):** תבנית תלת-ממדית המגדירה את ממדי העמודות באחוזים מדויקים (שוליים חיצוניים, טורים ראשיים, מרזב מרכזי עם קו מפריד אנכי, ושוליים ייעודיים להערות צד).
* **טיפוגרפיה תורנית מסורתית:** תמיכה בחלון פתיח שקוע (Drop Word) בגובה השורה הראשונה, הדגשת "דיבור המתחיל" (ד"ה) עד לנקודה או מקף, יישור שורה אחרונה של פסקה למרכז, ויישור לשני הצדדים של שורות שנקטעו ועוברות לעמוד הבא.
* **תוכן עניינים מפוצל:** אפשרות ליצירת תוכן עניינים כללי בראש הספר לצד תוכן עניינים מפורט בראש כל חלק, כולל מובילים מנוקדים, מספרי עמודים עדכניים וקיבוץ כותרות משנה לשורות מרוכזות.

```
│ ועקומת למידה    │ משנות ה-90      │ אך כבד ומסורבל  │ ואינטואיטיבי    │
└─────────────────┴─────────────────┴─────────────────┴─────────────────┘
```

1. **עקרון זרמי הטקסט הבלתי-תלויים:**
   בתוכנות כלליות כמו אינדיזיין או וורד, הערת שוליים כבולה גיאומטרית לשורה שבה נמצאת ההפניה. כתוצאה מכך, יצירת מבנה שבו גוף הטקסט מפוצל לשני טורים וההערות מרוכזות בטור אחד רחב גורמת לקריסה או לשבירות לא צפויות. בתוכנת "תג" ובסקריפטים מתקדמים (כגון FootWork), ההערות מנותקות לזרם טקסט עצמאי, ומעוגנות וירטואלית בלבד. מערכת ה-HTML שלנו מיישמת עקרון זה בהצלחה: תיבת ההערות יושבת כרכיב עצמאי בתחתית מעטפת העמוד, ומוזרקת ישירות לפני הפוטר.
2. **תורת שבירת השורות של קנות'-פלאס (Knuth-Plass):**
   אלגוריתם חמדן הסורק שורה-אחר-שורה מייצר "נחלים לבנים" וחוסר אחידות בולט. אלגוריתם קנות'-פלאס מעריך את הפסקה כיחידה אחת באמצעות תכנות דינמי. בספרות תורנית בעברית, שבה נמנעים לחלוטין משימוש במקף בסוף שורה, השגת צבע טיפוגרפי אחיד מתבצעת דרך מתיחה וכיווץ עדינים של רווחי מילים ושימוש באותיות מתרחבות (תכונת OpenType `jalt`).
3. **מנגנון מילוי, פיזור ומיטוב (Copyfitting):**
   פתרונות מובילים באינדיזיין (כגון חבילת iScript / MultiTextPager) ותוכנות וורד מבוססות AI (כגון RavText) מתבססים על מדידה מקדימה של פרקים שלמים. במקום לעמד עמודים מלאים ב-100% ולהשאיר עמוד אחרון ריק וכעור, המערכת מכווצת או מרחיבה בעדינות את גובה התוכן הזמין בכל עמודי הפרק, כך שכל העמודים מסתיימים בקו גובה מאוזן והרמוני.

1. **גלישת טקסט לתחום הערות השוליים (מקרה עמוד 47):** כאשר טור ימין התמלא, העמוד היה ריק מהערות. בטור שמאל נכנסה הערה ארוכה בת 12 שורות (כ-220 פיקסלים), שתפסה שטח נרחב בתחתית העמוד. אלגוריתם האיזון הישן ניסה לחלק את כל התוכן שנכנס ללא יכולת פליטה של עודפים לעמוד הבא, וכפה גלישה שרמסה את קו ההערות.
2. **מרכוז שגוי של שורה מקוטעת (מקרה עמוד 47):** פסקה שנחצתה בסוף הטור השמאלי וממשיכה בעמוד הבא קיבלה מחלקה של סוף פסקה רגילה, מה שגרם לשורת החיתוך להתמרכז במקום להימתח לשני הצדדים.
3. **אי-יישור תחתון ופערי גובה (עמודים 16, 32, 58, 66):** פערים של חצי שורה עד שתי שורות נוצרו כאשר שורות הועברו למניעת אלמנות ויתומות. תנאי סף נוקשה במנוע העימוד נכשל עקב עיגולי תתי-פיקסל של הדפדפן, ומנע את הפעלת שכבת היישור האנכי.
4. **סכנת כותרות יתומות (Heading Orphans):** בעת קיטוע עודפים בטור שמאל כדי לפנות מקום להערות שוליים, אם נחתכו כל שורות הפסקה שאחרי הכותרת – הכותרת נותרה תלויה לבדה בשורה התחתונה של הטור.
5. **התנגשות בין סוגרי הערות שוליים לכללי אלמנות ויתומות:** כאשר מנגנון ההגנה על סוגריים הזיז שורה כדי למנוע קריעה של הערה באמצע, הוא ביטל והפר את החלטת שומר השורות הבודדות, ויצר אלמנה או יתומה חדשה.
6. **היעלמות מילה ראשונה והערת צד בעמוד חדש (מקרה עמוד 49):** כאשר פסקה נדחפה במלואה (אפס שורות נשארו בעמוד הקודם), היא סומנה בטעות כפסקת המשך, ואיבדה את חלון המילה הראשונה ואת הערת הצד שלה.
7. **תופעת הבלוק הכפול באותו עמוד:** לאחר סיום מילוי שני טורים, מרווח פנוי קטן בתחתית העמוד יצר בלוק דו-טורי נוסף ללא כותרת רוחבית מפרידה, מה שגרם לטקסט לזרום ימין-עליון, שמאל-עליון, ימין-תחתון, שמאל-תחתון, ושבר לחלוטין את רצף הקריאה.
8. **מילה בודדת מתוחה (Runt) בשורה אחרונה של טור ימין:** נקודת חיתוך השאירה מילה אחת או שתיים בשורה האחרונה של הטור הימני, ושכבת רווחי המילים מתחה אותן בצורה לא אסתטית כדי לסגור פער גובה.
9. **עמודים קטועים וקצרים מדי לפני כותרת 3 (עמודים 33, 37):** כותרת רוחבית נכנסה כאשר נותרו בעמוד פחות מ-180 פיקסלים. שטח זה הספיק לכותרת עצמה אך לא הותיר מקום מספיק לגוף הטקסט מתחתיה, והעמוד נעצר באמצעו.
10. **באג ה-CSS Grid Stretch:** מאפיין מתיחה בגריד גרם לדפדפן לדווח על גובה שווה בשני הטורים גם כשטור שמאל היה ריק לגמרי, מה ששיבש את כל בדיקות ההתאמה ויצר חריגות ענק.
11. **באג קיפול השוליים (Margin Collapse) בעמודי כותרת 2:** חישוב הגובה התפוס סיכם שוליים עליונים ותחתונים בנפרד במקום למדוד את המרחק האמיתי ב-DOM, מה שגרם להערכת יתר של גובה הכותרת ולעמודים קצרים מדי.
12. **מירוץ טעינת גופני רשת (Font Loading Race Condition):** הרצת עימוד ראשוני טרם התייצבות גופני גוגל מדדה גופן חלופי נמוך, ויצרה עיוותי גובה ברגע שהגופן האמיתי נטען.
13. **שיבושי כותרות מתחלפות בעמודים זוגיים:** החלפת תוכן הכותרות ללא החלפת כיוון היישור גרמה לכותרת ימנית שעברה לשמאל להמשיך להתיישר לימין (פנימה לכיוון השדרה במקום החוצה).
14. **תקיעת הדפדפן בהקלדה (Browser Freeze):** עשרות פקדים בסרגל קראו לעימוד סינכרוני מלא בכל תנועת סליידר או הקשת מקש.
15. **קריאת נתונים שגויה מתיבת העורך:** שימוש שגוי במאפיינים שאינם נתמכים באלמנט עריכה גרם לאובדן טקסט בייבוא קבצים או באיפוס תבניות.

## חלק ד': פירוט הנקודות שעדיין דורשות פתרון וליטוש

אף שהקוד הנוכחי פתר את מרבית כשלי היסוד, כדי להגיע לשלמות מקצועית שתחליף את "תג" ואינדיזיין, נדרש לפתור 6 סוגיות עומק:

1. **מנגנון נסיגה מחזורי הרמטי (Unified Fixed-Point Rollback Loop):**  
   נדרשת לולאת פתרון מאוחדת המאמתת במקביל את כלל האילוצים: מניעת כותרת יתומה, שמירה על לפחות 2 שורות ליווי אחרי כותרת, מניעת שורה בודדת (אלמנה/יתומה), והגנה על שלמות סוגרי הערות שוליים. אם שינוי באחד הגורמים מפר גורם אחר, המערכת תבצע נסיגה איטרטיבית עד להתכנסות מלאה.
2. **מניעת מילים בודדות בשורה (Runt Prevention):**  
   איסור מוחלט על שבירת שורה המותירה מילה אחת או שתיים בלבד בשורה האחרונה של פסקה (במיוחד בטור הימני לפני מעבר לטור השמאלי). הפתרון יתבסס על הצמדת שלוש המילים האחרונות בתו רווח בלתי-נתיק בעת הפירוק לשורות.
3. **שכבת יישור אנכי רציפה (Continuous Vertical Justification):**  
   שיפור מנגנון 5 השלבים כך שיפעל בצורה חלקה ומשוקללת ללא תופעות של קפיצות גובה הפוכות (Overshoot), ויבטיח סגירה מלאה של פערי גובה של חצי שורה עד 2 שורות בכל עמודי הספר.
4. **איזון סוף-פרק בשיטת Copyfitting גלובלית:**  
   החזרת מדידת הנפח המקדימה של פרקים קצרים (2–4 עמודים) ופיזור אחיד של שטח העמודים, למניעת עמודים עמוסים ב-100% לצד עמוד אחרון שמכיל שורות בודדות.
5. **תמיכה באותיות מתרחבות (Justification Alternates / jalt):**  
   הטמעת תכונת OpenType מובנית או גופנים משתנים (Variable Fonts) בציר הרוחב, המאפשרים למערכת להרחיב אותיות עבריות מסורתיות (א, ד, ה, כ, ל, ם, ר, ת) במקום למתוח רווחי מילים בצורה מוגזמת.
6. **מערך בדיקות אוטומטי מבוסס מנוע דפדפן (Regression Suite):**  
   הקמת תשתית בדיקות אוטומטית המריצה את כל 1,000 שורות "מקום בינה" ובודקת בכל רינדור: אפס עמודי חריגה, אפס כותרות יתומות, אפס מילים בודדות, ואיזון טורים מדויק בסטייה של עד 2 פיקסלים.

### שלב 1: שדרוג ליבת האלגוריתם והטמעת לולאת נסיגה מאוחדת
* **איחוד בדיקות האילוצים:** שכתוב פונקציות ההתאמה כך שכל החלטת קיטוע תעבור דרך פותר אילוצים איטרטיבי.
* **כלל ליווי כותרות:** כותרת הנכנסת סמוך לתחתית טור תידחה אוטומטית לטור הבא אם לא נכנסות אחריה לפחות 2 שורות טקסט של הפסקה הבאה.
* **הגנה הרמטית על הערות שוליים:** סימון גבולות סוגרי ההערות בטקסט הגולמי, ופסילת נקודות חיתוך החוצות סוגריים מבלי לפגוע בכללי שורות יתומות ואלמנות.
* **נעילת בלוק דו-טורי יחיד לעמוד:** מניעת פתיחת בלוק דו-טורי שני באותו עמוד אלא אם נכנסה כותרת רוחבית מפרידה ביניהם.

### שלב 2: שכלול טיפוגרפי ומניעת פגמי מילים בודדות
* **מניעת מילים בודדות בשורה (Runt Prevention):** הטמעת מנגנון המצמיד אוטומטית את שלוש המילים האחרונות של כל פסקה בתווי רווח בלתי-נתיקים טרם החלוקה לשורות, מה שמבטיח ששום שורה אחרונה לא תכיל מילה בודדת.
* **כיול מנגנון 5 השלבים ליישור אנכי:** עדכון משקלי הריווח ומגבלות הסף כדי למנוע מתיחת יתר, והבטחת נעילה של שני הטורים על קו תחתון אחיד ברמת דיוק של פיקסל בודד.
* **שילוב אותיות מתרחבות:** הוספת תמיכה בתכונת OpenType `jalt` לגופנים תורניים תואמים, לשמירה על צבע טיפוגרפי הומוגני ביישור בלוק מלא.

### שלב 3: מנוע Copyfitting חכם לאיזון פרקים שלמים
* מדידת נפח התוכן הכולל של כל פרק בתיבת מדידה מכוילת בעלת רוחב טור וגופן אמיתיים.
* גזירת יחס מילוי אחיד לכל עמודי הפרק, למניעת עמודים מלאים ב-100% ועמוד אחרון ריק.

### שלב 4: ייצוב ממשק המשתמש, הנכסים והתבניות
* **שימור תבנית ניידת עצמאית (Self-Contained Export):** הבטחה שפונקציית שמירת התבנית תמזג את כלל קובצי ה-CSS, ה-JS והנכסים המיובאים לתוך קובץ HTML בודד הפועל ללא צורך בשרת.
* **ליטוש סרגל ההגדרות:** השלמת חיבור כל הפקדים הרדומים (כולל שליטה בממדי עיטורים, בחירת רקעים וטבלאות תוכן עניינים) ומניעת גלישת רכיבים מחוץ לסרגל.

### שלב 5: בדיקות אמפיריות מקיפות ומבחן מסמך האמת
* הרצת המערכת על גבי מסמך הבדיקה המלא ("מקום בינה" – 1,014 שורות, 303 הערות צד, 21 כותרות רוחביות).
* אימות ב-Headless Browser של כל דפי הספר: אישור שכל הטורים מאוזנים, אפס חפיפות עם קו הערות השוליים, אפס כותרות יתומות, ויישור שורות אחרונות תקין לחלוטין.

## 1. סקירת המערכת והארכיטקטורה (High-Level Overview)

### א. ייעוד התוכנה והמטרות התפקודיות
המערכת היא מנוע עימוד תורני ועורך שולחני (Desktop Publishing / DTP Engine) מבוסס טכנולוגיות ווב הפועל במלואו בצד לקוח (Client-Side Pure Web Architecture). ייעודה הוא הפקת ספרים תורניים מורכבים ברמת איכות ודייקנות של דפוס מסורתי, ללא תלות בשרת, ללא שלב קומפילציה (Build Step), וללא עלויות רישוי של תוכנות מדף מסורתיות.

המערכת מספקת מענה לפריסות עמוד מרובות:
1. **עמודי שער ומבואות:** שער ראשי, שער אחורי מודולרי בן 4 מקטעים, שערי משנה (חלקים).
2. **עמודי תוכן עניינים (TOC):** תוכן כללי מרובה עמודים בתחילת הספר ותוכן מפורט בראש כל חלק, הכוללים מובילים מנוקדים (Dot Leaders), חילוץ מספרי עמודים מדויקים בגימטריה ישירות מה-DOM לאחר פאגינציה, ומנגנון קיבוץ כותרות משנה לשורות רציפות (Grouped Headings).
3. **עמודי טקסט רגילים:** שני טורי גוף מקבילים, שוליים חיצוניים להערות צד (כותרת 7), כותרות רוחביות חוצות-טורים (כותרת 3 במצב `span_1col`), חלונות פתיח למילים ראשונות (Drop Words), הדגשת דיבור המתחיל (ד"ה), ואזור הערות שוליים עצמאי בתחתית העמוד מעל הפוטר.
4. **עמודי פתיחת סימן (כותרת 2):** התחלה מתחת לשליש עליון ריק, שורת סימן מובנית, עיטורים מותאמי-טקסט והצמדת גוף הטקסט לתחתית העמוד.
5. **עמודי הקדמה (כותרת 0):** זרימת טקסט בטור רחב יחיד.

### ב. טכנולוגיות, ספריות ודפוסי תכנון (Architectural Patterns)
* **שפות ליבה:** HTML5 תקני (Semantic & Paged), CSS3 (CSS Grid, Flexbox, CSS Custom Properties, Paged Media `@media print`), ו-JavaScript מודרני (ES2022+ / Vanilla JS).
* **ספריות חיצוניות:** אפס תלויות חיצוניות (Zero External Dependencies). לא נעשה שימוש ב-React, Vue, Webpack או מנועי צד-שרת. ייבוא גופנים מתבצע מ-Google Fonts כ-Fallback, עם תמיכה בגופני מערכת דרך `window.queryLocalFonts()` ובגופנים מקומיים דרך `@font-face`.
* **דפוס State:** ארכיטקטורת DOM-Driven State. פקדי הממשק בסרגל הצד (Sidebar) מהווים מקור אמת ראשוני לערכי תצורה (Configuration State), בעוד נתוני התוכן המעומד והחלוקה לדפים מנוהלים כמודל אובייקטים פנימי (Token Model) המתורגם ל-DOM. שמירת תבנית (`saveAsDefaultTemplate`) צורבת את הערכים ישירות לתוך ה-attributes של ה-HTML ומייצאת Data Island ב-JSON (`<script id="ext-imports-data" type="application/json">`).
* **דפוס רינדור (Rendering Engine Pipeline):**
  1. *Preprocessing:* ניקוי הערות עריכה (`stripEditorialNotes`), חילוץ מטא-דאטה מראש המסמך, פירוק לטוקנים (Tokenization) ואיחוד שורות של הערות רב-שורתיות (`mergeMultilineFootnoteSpans`).
  2. *Sectioning:* חלוקת המסמך למקטעי שערים, פתיחות סימנים (כותרת 2) וגוף תוכן.
  3. *DOM Measure & Flow:* פריסת הטקסט בתוך מיכל מדידה מוסתר (`#measuring-box`), מדידת שבירת שורות אטומית (`getLinesFromParagraph`), ובניית דפי A4 פיזיים (`.a4-page`).
  4. *Balancing & Trimming:* איזון טורים דו-שלבי בסופי פרקים ולפני כותרות רוחביות (`balanceColumns`), פליטת עודפים לעמוד הבא, ומתיחה אנכית מדורגת (`distributeColumnJustification`).
  5. *Footnote & Finalization:* שטיפת הערות שוליים לתחתית הדף (`flushFootnotesInto`), יישור מיקומי הערות צד, התאמת רוחבי עיטורים לטקסט וסנכרון תוכן עניינים.
* **הפרדת תהליכים (Threading & Responsiveness):** דפוס Deferred Execution / Debounced Pipeline. שינויי תצורה קלים (צבעי רקע, בוררי עיטורים) מוחלים מיידית דרך CSS Custom Properties; שינויי עימוד כבדים מושהים דרך Debounce של 400ms או מופעלים ידנית באמצעות לחצן "עדכן ועמד מחדש" המהבהב בעת שינויים ממתינים.

## 2. מכלול האלגוריתמים והבעיות שפתרנו (Deep Dive Implementation)

### א. עימוד ויישור שני טורים (Two-Column Layout & Balancing)

#### 1. בעיית היסוד
בסיום פרק או לפני כותרת רוחבית (`span_1col`, כותרת 3), זרימת שני הטורים בעמוד נקטעת. ללא איזון, טור ימין יתמלא במלואו עד תחתית הדף בעוד טור שמאל יכיל שורות בודדות או יישאר ריק לחלוטין.

#### 2. מבני הנתונים
* מערך `items`: רשימת אלמנטים ממוזגים בבלוק הנוכחי. עבור פסקאות (`type: 'p'`), האובייקט כולל: `lines` (מערך שורות גולמיות שנמדדו ב-DOM), `numLines`, `hasWindow`, `isCont`, `sideNote`, `endNote`. עבור כותרות (`type: 'h'`): `html`, `level`, `id`.
* מערך `splitPoints`: כל נקודות החיתוך האפשריות. נקודת חיתוך מוגדרת כ-`{ itemIndex, lineIndex, lines }`.

#### 3. אלגוריתם בחירת החיתוך המיטבי (`balanceColumns`)
הסריקה בוחנת את כל נקודות החיתוך האפשריות. עבור כל מועמד, מתבצעת הדמיית רינדור מהירה (`renderSingleItemFast`) ב-DOM עבור טור ימין ועבור טור שמאל, ונמדדים `rHeight` ו-`lHeight`.

פונקציית העלות (Cost Function):
$$\text{diff} = \text{rHeight} - \text{lHeight}$$
$$\text{absDiff} = |\text{diff}|$$
$$\text{balanceQualityScore} = \begin{cases} \text{absDiff} \times 0.6 & \text{if } 0 \le \text{diff} \le 24 \text{ px (בונוס למבנה עברי טבעי שבו ימין ארוך במעט)} \\ \text{absDiff} \times 1.3 & \text{if } \text{diff} < 0 \text{ (קנס חמור כאשר טור שמאל ארוך מטור ימין)} \\ \text{absDiff} & \text{otherwise} \end{cases}$$

בנוסף, מופעל קנס חריגה קשיח (Hard Budget Penalty):
$$\text{heightPenalty} = \begin{cases} (\text{rHeight} - \text{availH}) \times 5000 & \text{if } \text{rHeight} > \text{availH} \\ 0 & \text{otherwise} \end{cases} + \begin{cases} (\text{lHeight} - \text{availH}) \times 5000 & \text{if } \text{lHeight} > \text{availH} \\ 0 & \text{otherwise} \end{cases}$$
$$\text{Score} = \text{balanceQualityScore} + \text{heightPenalty}$$

המועמד בעל ה-Score המינימלי נבחר. מנגנון זה מבטיח שמועמד החורג מתקציב הדף הפנוי (`availH`) לעולם לא ינצח מועמד שנכנס בתקציב, גם אם המועמד החורג מאוזן יותר ברמת הפיקסל.

### ב. מניעת שורות וכותרות יתומות/אלמנות (Orphan & Widow Control)

#### 1. הגדרות טיפוגרפיות
* **אלמנה (Widow):** שורה אחרונה של פסקה העוברת לבדה לראש הטור או העמוד הבא (`lines.length - fit === 1`).
* **יתומה (Orphan):** שורה ראשונה של פסקה הנשארת לבדה בתחתית הטור או העמוד הנוכחי (`fit === 1`).
* **כותרת יתומה (Orphan Heading):** כותרת המוצבת בסוף טור ללא שורות טקסט של הפסקה הבאה מתחתיה באותו טור.

#### 2. אלגוריתם הזיכוך האיטרטיבי (`refineParagraphFitLine`)
כאשר נקבע קו חיתוך ראשוני לפסקה (`initialFit`) לפי גובה פנוי, הפונקציה מפעילה לולאת התכנסות המאזנת בין שומרי היתומות/אלמנות לבין תחומי סוגרי הערות השוליים:
1. `fit = adjustFitLineForNoteSpans(lines, fit)` — בדיקה האם נקודת החיתוך חוצה סוגריים של הערת שוליים (`[...]`). אם כן, הזזת החיתוך שורה קדימה או אחורה למקום בטוח.
2. `applyWidowOrphanToFitLine(lines, fit, pageHasContent)`:
   * אם `fit === 1` והעמוד כבר מכיל תוכן (`pageHasContent`): ביטול החיתוך והעברת כל הפסקה לעמוד/טור הבא (`fit = 0, forcePageBreak = true`).
   * אם נותרה שורה אחת בודדת להמשך (`lines.length - fit === 1`): אם `fit > 1`, משיכת שורה נוספת לאחור (`fit = fit - 1`), כך שלפחות שתי שורות יעברו יחד.
3. הלולאה חוזרת חלילה עד להתייצבות הערך (`fit === prev`) או עד תום 16 איטרציות הגנה.

#### 3. מניעת כותרות יתומות מראש (`canHeadingFitWithBody`)
לפני אישור הצבת כותרת בטור, המערכת מבצעת Probe מקדים ב-DOM של הטור:
1. הכותרת מוזרקת זמנית לטור.
2. נסרקות הכותרות העוקבות שאחריה (אם ישנן).
3. נדגמת פסקת התוכן הראשונה שבאה אחריה: מודדים האם נכנסות לפחות 2 שורות מעומדות של הפסקה (`needLines = 2`).
4. אם הטור חורג מתקציב הגובה (`targetCol.scrollHeight > availH`) — הכותרת נפסלת ואינה נכנסת לטור הנוכחי, אלא נדחית בשלמותה לראש הטור או העמוד הבא.

### ג. עימוד וניהול כותרות צד (Side Headings / Marginalia)

#### 1. עקרון הפעולה
כותרת 7 (וכל כותרת מרמות 4–6 שהוגדרה במצב `side_note`) מנותבת החוצה מזרימת הטקסט המרכזית אל טורי השוליים החיצוניים (`.right-margin` עבור טור ימין, `.left-margin` עבור טור שמאל).
הטוקן של הערת הצד מוצמד לפסקת התוכן הבאה ב-DOM דרך המאפיין `data-side-note`.

#### 2. אלגוריתם היישור ומניעת חריגות (`finalizeNotePositions`)
הערת הצד מוזרקת ב-`position: absolute` בטור השוליים, כאשר מיקום ה-`top` ההתחלתי שלה מושווה ל-`offsetTop` של פסקת היעד שלה.
כאשר הפסקה מתחילה סמוך לתחתית הטור, הערת הצד עלולה לחרוג מתחתית העמוד מעבר לקו סיום הטקסט. האלגוריתם מבצע מהלך דו-שלבי:
1. **הגבהה (Raise):** חישוב גובה החריגה מגבול הטור (`columnBoundaryHeight - noteHeight`). אם המרווח מול הערת הצד הקודמת שמעליה מאפשר זאת (`top >= prevBottom + 6`), הערת הצד מוגבהת כלפי מעלה וננעלת בקו התחתון.
2. **העברה לפסקת ההמשך (Transfer to Continuation):** אם אין מקום להגביה עקב צפיפות הערות מעל, האלגוריתם מאתר את קטע ההמשך של הפסקה בטור השמאלי (באמצעות `data-token-id` משותף ו-`data-is-cont="true"`). אם המיקום מול קטע ההמשך בטור שמאל פנוי מהערות אחרות — הערת הצד נשלפת מטור ימין, מועברת לטור שמאל, ומיושרת מול שורת ההמשך שלה.

### ד. מנגנון הערות שוליים בתחתית העמוד (Footnotes Positioning)

#### 1. ארכיטקטורת In-Flow מול Absolute
אזור הערות השוליים (`.footnote-area`) אינו ממוקם ב-`position: absolute` (אשר גרם בעבר לחפיפות עם הפוטר), אלא מוזרק כאלמנט In-Flow טבעי במעטפת ה-Flexbox של העמוד (`.page-content-wrapper`), ישירות לפני אלמנט הפוטר (`insertBefore(area, footer)`). חוקי ה-CSS Flexbox מונעים פיזית כל חפיפה בין תוכן ההערות לבין מספרי העמודים.

#### 2. שריון שטח דינמי בזמן אמת
בכל בדיקת התאמת גובה של פסקאות בטורים, מנוע העימוד קורא לפונקציה:
```javascript
getBlockColumnBudget(bodyFlow, pageEl, activeBlock, extraFootnoteQueue)
```
הפונקציה מנכה מתקציב הגובה הפנוי של הטורים (`totalFlowBudget`) את גובה כלל ההערות שנצברו עד כה בתור העמוד (`footnoteQueueForPage`), בתוספת גובה קו ההפרדה והשוליים שלו (`measureFootnoteAreaReserve`).
בנוסף, בעת מדידת שורות של פסקה המכילה הערות שוליים חדשות, מחושב מראש הגובה שתתפוסנה ההערות החדשות ברגע שתיכנסנה, והתקציב של הטור מתכווץ בזמן אמת *לפני* אישור כניסת השורה.

#### 3. שטיפה ומספור (Flushing & Numbering)
בסיום מילוי שני הטורים של העמוד, מופעלת הפונקציה `flushFootnotesInto(pageEl)`:
* תור ההערות נשטף לתוך רשת טורים ייעודית (1 או 2 טורים לפי הגדרת המשתמש).
* נוצר קו מפריד מעוצב (`buildNoteRuleElement`).
* כל סימון בטקסט מקבל עוגן היפר-טקסטואלי דו-כיווני (`<a href="#note-uid">` ו-`<a href="#noteref-uid">↩</a>`), השומר על פונקציונליות קישורים פנימיים לחיצים גם בעת ייצוא ישיר ל-PDF.
* מונה ההערות מתאפס לפי הגדרת המשתמש (בכל עמוד, בכל סימן, בכל חלק, או מספור רציף).

### ה. גלישת טקסט בין טורים ולאזור הערות השוליים (Area Overflow Handling & PushBack)

#### 1. מנגנון הקיטוע והפליטה (Trimming & PushBack)
אם לאחר שלב איזון הטורים מתברר כי גובה אחד הטורים חורג מתקציב הגובה המותר (`actualAvailH + 2`):
1. המנוע מפעיל לולאת PushBack מבוקרת השולפת את האלמנט האחרון מטור שמאל (או מטור ימין אם שמאל כבר ריק).
2. אם מדובר בפסקה — השורות שנשלפו ממוזגות חזרה לראש מבנה `pendingWordTokens`.
3. אם מדובר בכותרת — מונה הטוקנים מוחזר לאחור (`tokenIndex--`).
4. הבלוק המקוצץ מאוזן מחדש, והעודפים שנפלטו מועברים אוטומטית לעמוד הבא.

#### 2. מניעת מרכוז שגוי בשורות מקוטעות
כל פסקה שנחצתה עקב מעבר בין טורים או מעבר לעמוד הבא מתויגת במפורש במחלקה טיפוגרפית `class="p-cut"`.
ב-CSS מוגדר כלל דריסה מחייב:
```css
p.p-end { text-align-last: var(--last-line-align, center) !important; }
p.p-cut { text-align-last: justify !important; }
```
כלל זה מבטיח ששורה אחרונה של מקטע שנחתך ונמשך בעמוד הבא תישאר מתוחה לחלוטין משני צדדיה כשורת אמצע רגילה, ולעולם לא תתמרכז כאילו הייתה סוף פסקה.

### ו. יישור אנכי מדורג ב-5 רמות (Vertical Justification & Balancing)

כאשר נוצר פער גובה שיורי בין הטור הימני לשמאלי (עד 140 פיקסלים), מופעלת הפונקציה:

הפונקציה מפזרת את המרווח העודף באופן מבוקר ומדורג בשני מחזורים (חלוקה משוקללת ראשונית, וסגירת יתרת פער סדרתית) על פני 5 סדרי עדיפויות קשיחים:

## 3. יומן כישלונות, טעויות וניסיונות שנפסלו (Mistakes & Failed Approaches)

חלק זה מרכז את שרשרת הכשלים, ההשערות המוטעות והבאגים שנחשפו במהלך הפיתוח. התיעוד מפרט את סיבת הכשל ואת הכלל שנלמד כדי למנוע הישנות רגרסיות:

### כשל 1: באג ה-CSS Grid Stretch (חריגה מסיבית של 1,560px)
* **הגישה הראשונית:** מכולת שני הטורים הוגדרה ב-CSS Grid:
  ```css
  .block-2col {
      display: grid;
      grid-template-columns: var(--w-col) var(--w-col);
      align-items: stretch;
  }
  ```
* **באיזה תרחיש היא נכשלה:** במסמך הבדיקה המלא ("מקום בינה"). טור ימין התמלא עד 900px, ובשל `align-items: stretch` הדפדפן מתח אוטומטית גם את ה-box של טור שמאל (שהיה ריק עדיין) לאותו גובה של 900px.
* **כיצד הוכח הכשל:** מנוע האיזון קרא את `targetCol.scrollHeight` של טור שמאל, ראה שהוא שווה תמיד ל-900px (הפרש 0 מול ימין), הסיק בטעות שהתוכן מאוזן לחלוטין, והמשיך לדחוס עוד ועוד טקסט עד שגובה הטורים הגיע ל-1,560px (חריגה של 70% מעבר לגבול הדף).
* **המסקנה המחייבת:** אסור להשתמש ב-`align-items: stretch` בבלוק דו-טורי שמנוע ה-JS מודד בו גבהים. המאפיין שונה קבוע ל-`align-items: start;`.

---

### כשל 2: באג התאפסות גבהים בגלל `p { position: relative }`
* **הגישה הראשונית:** מדידת מיקומי שורות במנוע האיזון באמצעות `span.offsetTop`.
* **באיזה תרחיש היא נכשלה:** בקובץ ה-CSS הגלובלי הוגדר הכלל `p { position: relative; }`. עקב כך, כל פסקה הפכה ל-`offsetParent` עבור עצמה.
* **כיצד הוכח הכשל:** ערכי ה-`offsetTop` של המילים התאפסו ל-(2, 22, 42...) בכל פסקה מחדש במקום להימדד במצטבר מתחילת הטור. חישובי האיזון הניבו חוסר איזון קיצוני של 903px מול 355px.
* **המסקנה המחייבת:** במדידות פריסה של מילים ושורות, אסור להסתמך על `offsetTop`. יש להשתמש אך ורק ב-`getBoundingClientRect()` או `Range.getClientRects()`, ולחשב מרחק יחסי ע"י החסרת הקואורדינטה של ראש תיבת המדידה.

---

### כשל 3: באג ה-Float במדידת שבירת שורות (`splitTextIntoLines`)
* **הגישה הראשונית:** מדידת שבירת שורות ע"י הזרקת מילים עטופות ב-`<span>` והשוואת `p.offsetHeight` מצטבר.
* **באיזה תרחיש היא נכשלה:** בפסקאות המתחילות בחלון מילה ראשונה צף (`.first-word-window` עם `float: right`).
* **כיצד הוכח הכשל:** אלמנט צף (Float) אינו מותח את גובה מכולת הפסקה כאשר אין לצדו טקסט רגיל (בהיעדר Block Formatting Context). במדידת המילה הראשונה גובה הפסקה דיווח 0px. ברגע שנוספה המילה השנייה הגובה קפץ ל-21px, והאלגוריתם הסיק בטעות שהתרחשה שבירת שורה כבר אחרי המילה הראשונה! כתוצאה מכך נוצרו שורות מוזרות בנות מילה אחת בלבד. בנוסף, תיבת ה-float בגובה 1.875em גלשה לשורה השנייה וחסמה 40% מרוחבה.
* **המסקנה המחייבת:** אין להשתמש בסימולציית גבהים מילולית צעד-אחר-צעד בנוכחות Float. הפסקה מרונדרת פעם אחת במלואה, וקיבוץ השורות מתבצע ישירות לפי קואורדינטת ה-`top` הגיאומטרית שהדפדפן קבע לכל מילה.

### כשל 4: באג הספירה הכפולה ב-`measureRemainingHeight`
* **הגישה הראשונית:** הערכת גובה התוכן שנותר בפרק כדי לקבוע האם מדובר בסגירת פרק (`isSubClosing`) המצריכה איזון טורים.
* **באיזה תרחיש היא נכשלה:** כאשר בלוק קודם באותו עמוד חצה פסקה והותיר יתרת מילים ב-`pendingWordTokens`.
* **כיצד הוכח הכשל:** הפונקציה מדדה את יתרת המילים מתוך `pendingWordTokens`, ובמקביל סרקה את `subTokens`, שהאיבר הראשון שלו היה אותה הפסקה עצמה באורכה המלא המקורי! התוכן נופח מלאכותית פי 3.7 (1,943px מול 514px במציאות), המערכת סברה שהפרק לא ייכנס בעמוד, ביטלה את מנגנון האיזון, וסיימה את הפרק כשהטור השמאלי ריק לחלוטין.
* **המסקנה המחייבת:** כאשר קיים `pendingWordTokens`, חובה להחריג אוטומטית את הטוקן הראשון במערך המדידה כדי למנוע ספירה כפולה.

### כשל 5: באג קיפול השוליים (Margin Collapse) בעמודי כותרת 2

* **באיזה תרחיש היא נכשלה:** בעמודי פתיחת סימן שכללו כותרת, שורת סימן ועיטורים סמוכים.

### ב. קטעי קוד ליבה מרכזיים ומוכנים לייצור

#### 1. מנוע מדידת שורות אטומי עם הגנת הערות שוליים
קטע הקוד מתוך `typesetter.js` המבצע פירוק מדויק של פסקאות לשורות ב-DOM תוך הגנה על סוגרי הערות:

```javascript
function getLinesFromParagraph(text, colWidth, styleObj, useWindowIfMultipleLines) {
    const measureContainer = document.getElementById('measuring-box');
    measureContainer.style.width = colWidth + 'px';
    measureContainer.style.fontFamily = styleObj.fontFamily;
    measureContainer.style.fontSize = styleObj.fontSize;
    measureContainer.style.lineHeight = styleObj.lineHeight;
    measureContainer.style.textAlign = 'justify';
    measureContainer.style.textJustify = 'inter-word';
    measureContainer.style.direction = 'rtl';
    measureContainer.innerHTML = '';

    const fnOpen = document.getElementById('fn-delim-open')?.value?.trim() || '[';
    const fnClose = document.getElementById('fn-delim-close')?.value?.trim() || ']';
    let safeText = text.trim();

    // הגנה אטומית: החלפת רווחים בתוך סוגרי הערה בתו מוגן \uE000 למניעת שבירת ביטוי ההערה באמצע
    if (fnOpen && fnClose) {
        const escO = fnOpen.replace(/[-/\\^$*+?.()|[\]{}]/g, '\\$&');
        const escC = fnClose.replace(/[-/\\^$*+?.()|[\]{}]/g, '\\$&');
        safeText = safeText.replace(new RegExp(escO + '([\\s\\S]*?)' + escC, 'g'), (m, inner) => {
            return fnOpen + inner.replace(/\s+/g, '\uE000') + fnClose;
        });
    }

    const words = safeText.split(/\s+/);
    if (words.length === 0) {
        return { lines: [], hasWindow: false, numLines: 0 };
    }

    const pMeasure = document.createElement('p');
    pMeasure.style.margin = '0';
    pMeasure.style.padding = '0';
    pMeasure.style.lineHeight = styleObj.lineHeight;

    pMeasure.textContent = text;
    measureContainer.appendChild(pMeasure);
    const singleLineHeight = pMeasure.offsetHeight;
    pMeasure.textContent = "א";
    const oneLineH = pMeasure.offsetHeight;
    const numLinesEstimated = Math.max(1, Math.round(singleLineHeight / oneLineH));

    const minLines = parseInt(document.getElementById('drop-word-min-lines')?.value, 10) || 2;
    const mode = document.getElementById('drop-word-mode')?.value || 'window';
    const shouldApplyWindow = useWindowIfMultipleLines && (numLinesEstimated >= minLines) && (mode === 'window');

    const wordCount = parseInt(document.getElementById('drop-word-count')?.value, 10) || 1;
    const dropWords = words.slice(0, Math.min(wordCount, words.length)).join(' ').replace(/\uE000/g, ' ');

    let html = '';
    if (shouldApplyWindow) {
        html += `<span class="first-word-window" id="mw-0">${dropWords}</span> `;
        for (let i = wordCount; i < words.length; i++) {
            const w = words[i];
            const isNote = w.startsWith(fnOpen) && w.endsWith(fnClose);
            const displayW = isNote ? ' א ' : w.replace(/\uE000/g, ' ');
            html += `<span id="mw-${i}">${displayW}</span> `;
        }
    } else {
        for (let i = 0; i < words.length; i++) {
            const w = words[i];
            const isNote = w.startsWith(fnOpen) && w.endsWith(fnClose);
            const displayW = isNote ? ' א ' : w.replace(/\uE000/g, ' ');
            html += `<span id="mw-${i}">${displayW}</span> `;
        }
    }

    pMeasure.innerHTML = html;

    const lines = [];
    let currentLine = [];
    let currentTop = -1;
    const startIndex = shouldApplyWindow ? wordCount : 0;
    if (shouldApplyWindow) {
        currentLine.push(dropWords);
    }

    for (let i = startIndex; i < words.length; i++) {
        const span = document.getElementById(`mw-${i}`);
        if (!span) continue;
        const top = span.offsetTop;
        if (currentTop === -1) currentTop = top;
        const realWord = words[i].replace(/\uE000/g, ' ');
        if (Math.abs(top - currentTop) > 8 && currentLine.length > 0) {
            lines.push(currentLine.join(' '));
            currentLine = [realWord];
            currentTop = top;
        } else {
            currentLine.push(realWord);
        }
    }
    if (currentLine.length > 0) {
        lines.push(currentLine.join(' '));
    }

    measureContainer.innerHTML = '';
    return {
        lines,
        hasWindow: shouldApplyWindow,
        numLines: lines.length
    };
}
```

#### 2. פותר אילוצים מאוחד לחיתוך פסקה (Refine Fit Line)
```javascript
function refineParagraphFitLine(lines, initialFit, pageHasContent, maxFit) {
    let fit = Math.min(initialFit, maxFit);
    const hardMax = maxFit;
    for (let guard = 0; guard < 16; guard++) {
        const prev = fit;
        fit = adjustFitLineForNoteSpans(lines, fit);
        fit = Math.min(fit, hardMax);
        const wo = applyWidowOrphanToFitLine(lines, fit, pageHasContent);
        if (wo.forcePageBreak) {
            return { fit: 0, forcePageBreak: true };
        }
        fit = Math.min(wo.fit, hardMax);
        fit = adjustFitLineForNoteSpans(lines, fit);
        fit = Math.min(fit, hardMax);
        if (fit === prev) break;
    }
    return { fit, forcePageBreak: false };
}
```

## 6. מפת דרכים והצעדים הבאים (Roadmap & Pending Tasks)

### א. משימות פתוחות לשלב הבא

#### 1. מניעת מילה בודדת בשורה (Runt Prevention)
* *המטרה:* למנוע מצב שבו השורה האחרונה של פסקה (במיוחד בטור הימני לפני מעבר לטור השמאלי) מכילה מילה אחת או שתיים בלבד.
* *אופן המימוש המתוכנן:* בעת הכנת הטקסט ב-`getLinesFromParagraph`, חיבור שלוש המילים האחרונות של כל פסקה בתו רווח בלתי-נתיק (`\u00A0` / Non-breaking space), מה שכופה על הדפדפן להוריד לפחות 2–3 מילים יחד לשורה האחרונה.

#### 2. מנוע Copyfitting גלובלי לפרקים שלמים
* *המטרה:* למנוע מצב של עמודים עמוסים ב-100% לצד עמוד אחרון שמכיל שורות בודדות.
* *אופן המימוש המתוכנן:* חיבור מחדש של `estimateSectionFillRatio` בתיבת מדידה מכוילת ברוחב טור אמיתי (272px), וחישוב מקדם מילוי אחיד (`fillRatio`) המכווץ במתינות את גובה התוכן הזמין בכל עמודי הפרק.

#### 3. שילוב תכונת OpenType `jalt` (אותיות מתרחבות)
* *המטרה:* להשיג יישור שוליים הדוק ומסורתי בעברית ללא מתיחת רווחי מילים מוגזמת, כפי שנהוג בדפוסי וילנא הקלאסיים ובתוכנת "תג".
