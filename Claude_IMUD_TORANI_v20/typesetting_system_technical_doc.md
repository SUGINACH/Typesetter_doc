# מערכת עימוד תורנית לדפי A4 — תיעוד טכני מלא

מסמך העברה והתייחסות. מבוסס על הקבצים שנמסרו בסוף שיחת הפיתוח: `index.html`, `style.css`, `app.js`, `decorations.js`, `typesetter.js`.
מיועד למפתח או ל-AI שימשיך את העבודה. כל קטעי הקוד במסמך הוזרקו אוטומטית מהקבצים עצמם ולא הוקלדו מחדש.

## מקרא רמות אימות

כל טענה טכנית במסמך מסומנת ברמת האימות שלה. אלה לא קישוטים: חלק ניכר מהכשלים המתועדים בסעיף 3 נבעו מכך שטענה שנבדקה ברמה אחת הוצגה כאילו נבדקה ברמה גבוהה יותר.

| סימון | משמעות |
|---|---|
| **[E]** | נבדק בהרצה בפועל: בדיקה, סקריפט או `grep`/`diff` שניתנים לשחזור. קוד הבדיקות מצורף בסעיף 7. |
| **[R]** | נבדק בקריאת קוד בלבד. לא הורץ. |
| **[U]** | לא ניתן לאימות בסביבה שהייתה זמינה. דורש דפדפן אמיתי עם מנוע layout. |

**הסתייגות יסוד.** שום חלק במערכת לא אומת חזותית. סביבת הבדיקה (Node.js + jsdom) אינה מחשבת layout: `scrollHeight`, `offsetHeight`, `offsetTop` ו-`getBoundingClientRect` מחזירים ערכים ריקים או מדומים. לכן `performTypeset()` כולו לא הורץ מקצה לקצה אף פעם. מה שכן הורץ: פונקציות ההחלטה הטהורות (`decideParagraphCut`) ו-`balanceColumns` עם מודל גבהים דטרמיניסטי. כל טענה על "נראה נכון", "מיושר" או "ללא גלישה" ברמת הדף השלם היא **[U]** עד בדיקה בדפדפן.

## 1. סקירת המערכת והארכיטקטורה (High-Level Overview)

### 1.1 ייעוד

אפליקציית ווב עצמאית (קובצי סטטי, ללא שרת) לעימוד ספרים תורניים לדפוס. הקלט: טקסט גולמי עם סמני כותרות בעברית (`כותרת 2 - ...`, `כותרת 7 - ...`) והערות שוליים בתוחמים (ברירת מחדל `[` ו-`]`). הפלט: רצף אלמנטי `.a4-page` (210×297 מ"מ) בתוך `#book-container`, הניתן להדפסה או לשמירה כ-PDF דרך הדפדפן. מאפיינים ייחודיים לעימוד תורני שהמערכת מטפלת בהם: שני טורים עם יישור אנכי, הערות שוליים והערות סיום, הערות צד בשוליים (marginalia), היררכיית כותרות 0–7 עם מצבי עימוד שונים לכל רמה, מספור סימנים, מילה ראשונה מוגדלת ("חלון"), דיבור המתחיל, שערים (ראשי, משנה, אחורי), תוכן עניינים כללי ומפורט, מספור עמודים באותיות עבריות (גימטריה), ועיטורים.

### 1.4 תבנית ארכיטקטונית: בנייה מחדש מלאה (Immediate-Mode Rebuild)

המערכת אינה MVC ואינה MVVM. אין שכבת מודל מתמשכת. מקור האמת הוא:

1. הטקסט הגולמי ב-`#raw-input` (div עם `contenteditable`).
2. ערכי כל פקדי לוח ההגדרות (`input`, `select`, `checkbox`), הנקראים ב-`document.getElementById(...)` **ברגע השימוש**, לא נשמרים במטמון.

`performTypeset()` היא פונקציה שמקבלת את שני אלה ובונה מחדש את כל `#book-container` מאפס בכל הרצה. אין עדכון הדרגתי (incremental), ואין השוואת מצב קודם. לכך שתי תוצאות מעשיות:

- **כל כלל עימוד מוחל מחדש במלואו בכל הרצה**, בלי קשר לשינוי הקודם. כללי היתומות והאלמנות נקראים מה-DOM בכל החלטת חיתוך (`document.getElementById('avoid-widows')?.checked ?? true`), כך שאין מצב שבו דגל "תקוע" ממופע קודם **[R]**.
- המחיר: כל הרצה היא O(מסמך) ממדידות DOM סינכרוניות. ראו סעיף 1.7.

```
 #raw-input ──getCleanEditorText()──────────────────────────┐
 לוח הגדרות ──updateGrid()/updateStyles()──► CSS custom properties על <html>
                                                             │
 performTypeset():                                           ▼
   stripEditorialNotes → parseMetadataFromText → טוקניזציה (כותרות/פסקאות/הערות צד)
   → חלוקה לחלקים לפי כותרת 1 → לכל חלק: שער משנה / תוכן עניינים / דפים
   → לולאת דפים: createPageLayout → מילוי טור ימין → מילוי טור שמאל
        → balanceColumns / justifyColumnVertically → הערות שוליים (flush)
   → מעברי סיום (divider גובה, applyHeadingOrnamentTextFit, גודל תצוגה)
   → #book-container: ‎.a4-page × N
```

### 1.6 מצב גלובלי (typesetter.js)

מונים ותורים המאופסים בתחילת כל `performTypeset()`: `noteCounters` (`{footnote, endnote}`), `noteUidCounter`, `footnoteQueueForPage` (הערות ממתינות לעמוד הנוכחי), `endnoteQueueForPart` (הערות סיום לחלק הנוכחי). כל איפוס הכרחי: מונים שלא אופסו גורמים לספירת הערות שממשיכה בין הרצות. ב-`balanceColumns` המצב נשמר ב-`snapshot` ושוחזר לפני כל רינדור מחדש כדי שמספור ההערות יישאר דטרמיניסטי (סעיף 2.5).

### 1.7 מודל הפעלת העימוד: שער "עדכן ועמד מחדש"

**הבעיה** שהוגדרה בשימוש: שינוי הגדרה אחד מפעיל עימוד מלא של כל המסמך על ה-thread הראשי, והדף נתקע. ב-HTML היו 205 מקומות שקראו ל-`typesetDocument()`, מהם 78 על `oninput` (כל תו או כל תזוזת סליידר). כבר היה debounce של 400ms; הוא לא פתר את הבעיה, כי הריצה היחידה שאחריו כבדה בעצמה. **[R]**

**הפתרון בקוד הנוכחי** (שלוש חוליות):

1. **שינוי בלוח** ← מאזיני `input`/`change` מרכזיים על `#settings-pane` (`initSettingsChangeListeners`) ← `markPendingChanges()` מוסיף את המחלקה `has-pending-changes` לכפתור `#btn-retypeset` (הבהוב כתום).
2. **חריג: הגדרות מקומיות וזולות** (בחירת שער/ערכה/רקע, מזהים שמכילים `shaar`/`theme`/`cbg-`/`builder-`) ← `typesetDocumentLive()` עם debounce של 350ms, ללא שער.
3. **לחיצה על הכפתור** ← `typesetDocument()` (עם `delay = 0`) ← `performTypeset()` מיידי, והסרת ההבהוב.

**אזהרה לממשיך:** המשמעות של `typesetDocument` שונה בין קווי הפיתוח השונים שמוזגו. בקוד הנוכחי היא "הרץ עכשיו" (עם עיכוב אופציונלי). בקווים אחרים (כולל זה שבניתי בשלב מוקדם בשיחה) היא רק סימנה "יש שינויים ממתינים". לפני שמוסיפים קריאה חדשה — לקרוא את `typesetDocument`, `typesetDocumentLive` ו-`markPendingChanges` בקוד הנוכחי. **[R]**

### 1.8 מנוע המדידה

העימוד מבוסס **מדידה**, לא חישוב אנליטי. שום גובה שורה או רוחב מילה לא מחושבים מנתוני גופן; הכל נמדד ב-DOM אמיתי:

- **גיאומטריית עמוד:** `.a4-page` ברוחב 210mm וגובה 297mm עם `padding: 15mm`, כלומר שטח תוכן של 180×267 מ"מ. `overflow: hidden` על העמוד: **תוכן שחורג נחתך בשקט ולא מוצג**. לכן באג גלישה נראה כטקסט שנעלם או נעצר, לא כטקסט שיוצא מהדף. **[R]**
- **שבירת שורות:** `getLinesFromParagraph` מרנדרת כל מילה כ-`<span id="mw-i">` בתוך `#measuring-box` נסתר ברוחב הטור, ומזהה שבירת שורה לפי שינוי ב-`offsetTop` בין מילים עוקבות (סף 8px). סעיף 2.3.
- **בדיקות התאמה:** אחרי הוספת כל שורה. בנתיב הטור היחיד: `targetCol.scrollHeight ≤ availH`; בנתיב שני הטורים: `pElem.offsetTop + pElem.offsetHeight ≤ cachedAvailH` (סעיף 2.4).
- **בדיקות הערות שוליים:** `measureNoteBlockHeight` בונה בלוק הערות אמיתי בתוך ה-DOM, מודדת `offsetHeight`, ומסירה. כל קריאה גוררת reflow. סעיף 2.8.
- **אין threading.** כל העימוד סינכרוני על ה-thread הראשי. Web Worker אינו אפשרי כי המדידה דורשת DOM.

## 2. מכלול האלגוריתמים והבעיות שנפתרו (Deep Dive Implementation)

### 2.1 קריאת קלט וטוקניזציה

**שלבים** (בתוך `performTypeset`, לפי הסדר):

1. **קריאת הטקסט.** `getCleanEditorText()`. העורך הוא `<div id="raw-input" contenteditable>` שבנוי משורות `.editor-line`. ב-`app.js` מוגדר shim: `Object.defineProperty(editorElem, 'value', {get: getCleanEditorText, set: renderEditorContent})`, כך ש-`editorElem.value` עובד גם על div. אם הטקסט ריק אחרי `trim()` — יציאה מיידית. (ראו כשל F16 בסעיף 3: טענה שגויה לגבי נקודה זו.)
2. **`stripEditorialNotes`.** מסירה קטעים בין סמני `##…##` (הערות עריכה), מצמצמת רווחים/טאבים כפולים, מסירה רווח לפני `,.:;!?`, ומבצעת `trim`. **תופעת לוואי:** נרמול פיסוק גלובלי על כל הטקסט, כולל טקסט שבו הרווח לפני פיסוק מכוון. **[R]**
3. **`parseMetadataFromText`.** מסירה מהטקסט שורות מטא-דאטה בתבניות קבועות (שם הספר, נושא, נושא מפורט, פרטי מהדורא, שם המחבר, מקום ושנה), מעדכנת איתן את שדות השער ב-`index.html`, ומעבירה הלאה כל שורה אחרת ללא שינוי. **[R]**
4. **צמצום רווח לפני תוחם פותח של הערת שוליים.** הרווח לפני `fnOpen` נמחק כדי שההערה תידבק למילה שלפניה. הסיבה: אחרת מתאפשרת שבירת שורה בין המילה להערה, ומופיעה שורה בודדת (יתומה). **[R]**
5. **לולאת שורות.** כל שורה נבדקת לפי הסדר: (א) **כותרת**: `/^כותרת\s*(\d+).*?[-–—]\s*(.*)$/`. **המקף (`-`, `–` או `—`) חובה**; שורה `כותרת 3 טקסט` בלי מקף היא פסקה רגילה, בשקט. הרמה היא כל מספר שלם. (ב) אחרת: סגנון טקסט מיובא עם `trigger.type === 'linePrefix'` ו-`line.startsWith(prefix)` (ההתאמה הראשונה מנצחת). (ג) אחרת: פסקה. **[R]**

**סינטקס קלט** (אמיתי, מתוך הקובץ שנבדק):

```
שם הספר - ספר מלכי המלוכה
נושא - ביאורים וחידושים עמוקים
כותרת 2 מספר 2 - הלכות שבת
פסקה רגילה עם הערת שוליים [טקסט ההערה] שממשיכה הלאה.
כותרת 7 - הערת צד שתוצג בשולי העמוד
```

**סכמת טוקן:**

| שדה | משמעות |
|---|---|
| `id` | מזהה ייחודי; משמש ב-`data-token-id` לחיבור חלקי פסקה שנחתכה |
| `type` | `'p'` או `'h' + רמה` |
| `level` | 0–7 לכותרות |
| `text` | התוכן (HTML חלקי לאחר `applyDelimiterStyles`) |
| `lineIdx` | מספר השורה במקור (לסנכרון עורך ← תצוגה) |
| `customStyleId` | סגנון טקסט מיובא שהפעיל את השורה |
| `sideNote`, `sideNoteStyleId` | טקסט הערת צד שצמוד לפסקה זו (ראו 2.7) |
| `endNote` | הערת סיום מצורפת |

**מקרים מיוחדים בטוקניזציה:**

- **כותרת Run-in** (מצב `run_in`): הכותרת אינה הופכת לטוקן. היא נשמרת ב-`pendingRunInHeading` וקודמת לטקסט הפסקה הבאה כ-`<span class="heading-run-in title-level-N">…</span>`.
- **כותרת הערת צד:** **רק כותרת 7** במצב `side_note` (תנאי מפורש: `lvl === 7 && mode-h7 === 'side_note'`), או סגנון טקסט מיובא עם `layoutMode: 'side_note'`. היא אינה הופכת לטוקן: הטקסט נשמר ב-`pendingSideNote` ומוצמד לטוקן הפסקה הבאה כ-`sideNote`. **פער:** הבוררים של כותרות 5 ו-6 מציעים את הערך `side_note`, אך שום קוד אינו מטפל בו עבורן (`grep side_note` מצא שלוש הופעות בלבד: שורות 1561, 1600, 1658). בלולאת העמודים כל מצב שאינו `span_1col` מטופל כ-`inline_2col`, כלומר הבחירה מתנהגת כמו `inline_2col`. **[E]** (`grep`) **[R]** (ההתנהגות).
- **חלוקה לחלקים:** לפי כותרת 1 (`h1`). כל חלק מקבל שער משנה (מצב `sub_shaar`) ותוכן עניינים מפורט אופציונלי.
- **מצב עימוד לכל רמה:** נבחר ב-`mode-h0` עד `mode-h7`. הערכים: `new_page_1col` (טור יחיד, עמוד חדש), `span_1col` (טור יחיד רציף ברוחב מלא), `inline_2col` (בתוך זרימת שני הטורים), `side_note`, `sub_shaar`, `run_in`.

קובץ הבדיקה שהועלה בשיחה (`חלק_ההקדמה_סדר_חדש.txt`): 1009 שורות, 273,129 תווים. התפלגות כותרות (נמנה ישירות מהקובץ): כותרת 0 ×1, כותרת 1 ×1, כותרת 2 ×5, כותרת 3 ×21, כותרת 4 ×55, כותרת 5 ×14, כותרת 6 ×15, כותרת 7 ×303. תשעה זוגות תוחמים `[ … ]` (הערות שוליים), כל אחד בשורה נפרדת.

### 2.2 גיאומטריית עמוד ורשת הטורים

- **קופסת העמוד:** `.a4-page` ברוחב 210mm, גובה 297mm, `padding: 15mm`, `overflow: hidden`. שטח תוכן: 180×267 מ"מ. **[R]** (נקרא ישירות מה-CSS.)
- **רשת שבעה טראקים** ב-`.block-2col`: `margin | gap | col | gutter | col | gap | margin`. ב-RTL הטראק הראשון בימין. הטור הימני = `grid-column: 3`, השמאלי = `5`. עמודות השוליים (`.margin-notes-column`) = טראקים 1 ו-7, ובהן יושבות הערות הצד.
- **נרמול:** `updateGrid()` קוראת ארבעה ערכים (`prop-col`=40, `prop-margin`=7.5, `prop-gutter`=2, `prop-gap`=2 כברירות מחדל), מחשבת `total = 2·col + 2·margin + gutter + 2·gap` ו-`scale = 100/total`, וקובעת `--w-col`, `--w-margin`, `--w-gutter`, `--w-gap` כ-`ערך × scale` באחוזים. כלומר הערכים שהמשתמש מזין הם **יחסים**, לא אחוזים מוחלטים: ברירות המחדל סוכמות ל-101 והמערכת מנרמלת אותן ל-100. בנוסף קובעת `--flow-mt`, `--flow-mb` ו-`--flow-mt-h2` (ברירת מחדל 20px) מ-`prop-mt`, `prop-mb`, `prop-mt-h2`. **[R]**
- **תקציב גובה:** `remPageHeight = isFirstPage ? totalFlowH − used : totalFlowH`. `totalFlowH` הוא גובה `.page-body-flow` הפנוי. `used` בעמוד פתיחה = `offsetHeight` של `.h2-spacer` + לכל אחד מ-`.h2-ornament-top`, `.h2-siman-badge`, `.title-level-2-standalone`, `.h2-ornament-bottom`: `offsetHeight + marginTop + marginBottom` (הכותרת מדולגת כשהיא בתוך `.block-h2-title-side`). **[R]** נקודה חשובה: זהו חישוב חד-פעמי בזמן בניית העמוד. עיטורים שגודלם משתנה אחר כך (ראו `applyHeadingOrnamentTextFit`, סעיף 2.12) אינם מעודכנים בו.
- **כותרות `span_1col`:** בלוק נפרד ברוחב מלא (`.block-h3-span` וכד'), לא חלק מ-`block-2col`. הגובה שלו מוחסר מ-`remPageHeight`.

### 2.3 שבירת שורות (Line Breaking)

**בעיה:** כדי להחליט כמה שורות של פסקה נכנסות בטור, צריך לדעת איפה הדפדפן יישבר שורה, כולל השפעת יישור מוצדק (`justify`), גופן, ומילה ראשונה צפה.

**פתרון:** `getLinesFromParagraph(text, colWidth, styleObj, useWindowIfMultipleLines)`:

1. יוצרת אלמנט מדידה נסתר ב-`#measuring-box` ברוחב הטור עם `text-align: justify`, `direction: rtl` והגופן והגודל הנוכחיים.
2. מפצלת את הטקסט למילים. **תוכן כל הערת שוליים (בין `fnOpen` ל-`fnClose`) הופך ליחידה אטומית**: כל הרווחים שבתוכו מוחלפים בתו Private-Use `\uE000`, כך שפיצול לפי רווח מתייחס אליה כמילה אחת ולא ייתכן חיתוך בתוכה.
3. כל מילה מרונדרת ל-`<span id="mw-i">`. **למדידה בלבד, הערה מוצגת כ-`' א '`** (אות בודדת) ולא בתוכנה האמיתי, כי בעימוד הסופי רק מרקר קצר מופיע בגוף הטקסט והטקסט עצמו בתחתית העמוד. המילים האמיתיות משוחזרות (`\uE000` → רווח) אחרי המדידה.
4. **מילה ראשונה מוגדלת ("חלון"):** אם `drop-word-mode === 'window'` והפסקה מוערכת כבעלת לפחות `minLines` שורות, N המילים הראשונות מרונדרות כ-`<span class="first-word-window" id="mw-0">` (צף), ולכן הציפה משפיעה על שבירת השורות שלידה.
5. מזהה שבירת שורה: `Math.abs(span.offsetTop − currentTop) > 8` בין מילה למילה.
6. מחזירה `{lines: string[], hasWindow, numLines}`.

**מגבלות ידועות** **[R]**: הסף 8px הוא היוריסטיקה; הוא תקין לשורות בגובה סביר ולא יזהה שבירה בשורות נמוכות מ-8px. החישוב מתבצע לרוחב טור יחיד; פסקה שממשיכה בין הקשרים ברוחבים שונים (טור יחיד לעומת שני טורים) לא נמדדת מחדש ברוחב החדש.

### 2.4 לולאת המילוי: מילוי חמדני לפי טור

מבנה (פסאודו-קוד, מבוסס על הקוד):

```
לכל עמוד:
  pageLayout = createPageLayout(...)              // כותרת עליונה + bodyFlow + מספר עמוד
  remPageHeight = totalFlowH (− used בעמוד פתיחה)
  כל עוד (remPageHeight − getFootnotesReservedHeight()) > 45 וקיימים טוקנים:
     אם הטוקן הבא הוא כותרת span_1col:           → בלוק ברוחב מלא; בדיקת מקום; keep-with-next
     אחרת: block2Col = grid בן 7 טראקים; לכל colName ב-['right','left']:
            targetCol = rCol או lCol
            כל עוד נכנס: הוסף טוקן
              פסקה → getLinesFromParagraph → לולאת bestFitLine → decideParagraphCut → רינדור chunk
              כותרת inline → הוספה; אם הפסקה שאחריה נדחתה — הכותרת נמחקת ונדחית איתה
     ואז: בחירת איזון (סעיף 2.5, ארבעה תנאים)
     remPageHeight −= גובה הבלוק
  flushFootnotesInto(עמוד קודם) בתחילת העמוד הבא
```

**נקודה מהותית:** המילוי הוא **חמדני לכל טור בנפרד**: קודם הטור הימני מתמלא עד הגובה הפנוי, ואז השמאלי. רק אחר כך `balanceColumns` מפזרת מחדש את התוכן המשולב בין שני הטורים. לכן בסוף חלק הטור הימני מלא והשמאלי חלקי, עד שהאיזון מתקן. **[R]**

**שני נתיבי מילוי** (הם אינם זהים, וזה מקור לפערים):

| נתיב | מתי | רוחב מדידה | תנאי התאמה | זיהוי מוקדם של הערות |
|---|---|---|---|---|
| **טור יחיד** (`block-single-col`, `.single-wide-col`) | `isH0 = sec.isNewPage && sec.hToken.level === 0 && !sec.is2ColNewPage`: כל חלק שנפתח בכותרת 0 במצב `new_page_1col`, **בכל עמודיו** ("מקרה הקדמה") | **580 קשיח** (`getLinesFromParagraph(…, 580, …)`, שורה 2038) | `targetCol.scrollHeight ≤ remPageHeight − getFootnotesReservedHeight()` | **אין** |
| **שני טורים** (`block-2col`) | כל שאר החלקים | `colWidth` | `pElem.offsetTop + pElem.offsetHeight ≤ cachedAvailH` | **יש** (`pendingFnMatches`) |

**נקודה חשובה לשימוש בפועל:** המסמך האמיתי שנבדק בשיחה פותח ב-`כותרת 0`, כלומר הפרק הראשון שלו עובר דרך נתיב הטור היחיד, שהוא הפחות מתוחזק: רוחב המדידה (580px) שונה מרוחב הטור האמיתי (שטח התוכן 180mm ≈ 680px), ולכן מספרי השורות שמחושבים (ושעליהם מתבססים כללי היתומות/האלמנות) אינם מתאימים לשורות שהדפדפן מרנדר. ההתאמה הפיזית (`scrollHeight`) נמדדת ב-DOM אמיתי ולכן נכונה; הטעות היא בספירת השורות. **[R]**

**בדיקת התאמה לפסקה בנתיב שני הטורים (`bestFitLine`):**

```
fullRemainingText = lines.join(' ')
pendingFnMatches  = findDelimiterMatches(fullRemainingText, 'body')   // רק הערות שוליים
cachedAvailH      = remPageHeight − getFootnotesReservedHeight()
bestFitLine = 0
לכל i = 1..lines.length:
   רנדר lines[0..i) לתוך pElem
   אם יש pendingFnMatches: newOnes = ההערות שנגמרות לפני סוף testText
        אם מספרן השתנה: cachedAvailH = remPageHeight − (מדידת בלוק הערות היפותטי
                         של התור הנוכחי + newOnes, + 24)
   אם pElem.offsetTop + pElem.offsetHeight ≤ cachedAvailH → bestFitLine = i
   אחרת break
```

`pendingFnMatches` מזהה מראש (לפני הלולאה) את כל ההערות בטקסט הפסקה. בלי זה, גובה ההערות של הפסקה עצמה לא נלקח בחשבון בבדיקת ההתאמה שלה, ובלוק ההערות בפועל גדל מעבר למה שנשמר. ההערות ההיפותטיות נמדדות עם מספר-מציין `'א'` ו-uid `probe<k>`. ראו כשל F12. **הנתיב הראשון (`isH0`) אינו כולל מנגנון זה.**

### 2.5 עימוד ויישור שני טורים (Two-Column Balancing)

`balanceColumns(block, colWidth, styleObj, snapshot, availableHeight)` לוקחת את התוכן שנצבר בשני הטורים ומפזרת אותו מחדש כך שהטורים שווים בגובה ככל האפשר, בכפוף לשלושה אילוצים: נכנס בגובה העמוד, אין שורות בודדות, אין כותרת בתחתית הטור הימני.

**מבנה הנתונים.** פריטים (`items`): `{type:'p', id, rawText, isCont, lines, numLines, hasWindow, isSingleLine}` או `{type:'h', html}`. פסקה שנחתכה קודם בין הטורים ממוזגת בחזרה לפריט אחד לפי `data-token-id`.

**אלגוריתם:**

1. **שחזור מצב הערות** מ-`snapshot` (תורים, מונים, `noteUidCounter`) כדי שרינדור חוזר ייתן את אותו מספור.
2. **איסוף פריטים** מ-`rCol` ואחר כך `lCol`, ומיזוג חתיכות עוקבות של אותו `id`.
3. **חישוב שורות** לכל פסקה ברוחב הטור.
4. **יצירת נקודות חיתוך** `{itemIndex, lineIndex}`: לפני כל פריט (`lineIndex = 0`), בתוך כל פסקה בין שורה `l` ל-`l+1` עבור `l = 1…L−1`, ובסוף הרשימה.
5. **סינון נקודות** (סעיף 2.6): `avoidWidows && l === 1` נפסל; `avoidOrphans && L − l === 1` נפסל; חיתוך מיד אחרי כותרת נפסל. אם כל הנקודות נפסלו, חוזרים לרשימה המלאה.
6. **הערכה** של **כל** נקודה חוקית (לא חיפוש בינארי): בונים את הטור הימני (פריטים לפני החיתוך + `l` שורות ראשונות) ואת השמאלי (השאר) ב-`renderSingleItemFast`, מודדים `scrollHeight` של שניהם. הערות מרונדרות במצב "ריצה יבשה" (`applyDelimiterStyles(..., true)`): מרקר מוצג כדי שגובה השורה יהיה נכון, אך שום הערה לא נכנסת לתור.
7. **ציון:** `score = |rHeight − lHeight| + heightPenalty`, כאשר `heightPenalty = Σ max(0, h − availableHeight) × 2000` על שני הטורים (רק כש-`availableHeight` סופי). הציון הנמוך ביותר נבחר; בשוויון, עדיפות ל-`diff ≥ 0` (ימין גבוה או שווה לשמאל).
8. **רינדור סופי** של הנקודה הנבחרת (`appendItemFinal`), הפעם עם הכנסת הערות לתור, ושמירת רשימת הערות הצד הסופית.
9. **יישור אנכי עדין** (`justifyColumnVertically`) לטור הקצר אם הפער הסופי גדול מ-2 ועד 60 פיקסלים (פירוט להלן).
10. **מיקום הערות צד** (`finalizeNotePositions`) וקביעת גובה קו המפריד האנכי ל-`Math.min(rCol.scrollHeight, lCol.scrollHeight)`.

**למה `×2000`:** קנס הגלישה גדול בסדרי גודל מהפער בין טורים, כך שחלוקה מאוזנת לחלוטין שגולשת תמיד תפסיד לחלוקה לא מאוזנת שנכנסת. התנהגות זו **[E]**: ב-2400 מקרים שבהם קיימת חלוקה שנכנסת — נבחרה חלוקה שנכנסת; ב-1600 מקרים שבהם אין כזו — נבחרה הגולשת הכי פחות.

**ארבעת התנאים להפעלת האיזון** (מתוך `performTypeset`, אחרי מילוי שני הטורים):

| # | תנאי | פעולה |
|---|---|---|
| 1 | סוף החלק (`tokenIndex ≥ secTokens.length` ואין פסקה ממתינה) | `balanceColumns` + הוספת מפריד סיום פרק |
| 2 | הטוקן הבא הוא כותרת `span_1col` | `balanceColumns` |
| 3 | `rCol.scrollHeight > actualAvailH` או הפרש בין הטורים גדול מ-60px | `balanceColumns` |
| 4 | אחרת, והבלוק נכנס | אם 2 < הפרש ≤ 60 — `justifyColumnVertically` לטור הקצר בלבד |

**`justifyColumnVertically(col, targetHeight, styleObj)`:** מחשבת `diff = targetHeight − col.scrollHeight` ופועלת רק אם `2 < diff ≤ 60`. אם בטור יותר מפסקה אחת (`p`): מחלקת `diff / (n − 1)` כתוספת ל-`margin-bottom` של כל הפסקאות **חוץ מהאחרונה** (כותרות אינן מקבלות תוספת). אם יש פסקה אחת בלבד: מגדילה את `line-height` שלה ב-`(diff / numLines) / fontSizePx`. מעל 60px היא אינה פועלת, כדי לא ליצור ריווח מוגזם. **[R]**

**סיבוכיות:** O(S·N) מדידות DOM, כאשר S מספר נקודות החיתוך החוקיות (בערך מספר השורות בבלוק) ו-N מספר הפריטים שמרונדרים בכל הערכה. כל הערכה גוררת שני reflow.

**הוכחה בהרצה [E]:** `balanceColumns` האמיתית הורצה על 2600 תרחישי איזון אקראיים ועוד 800 תרחישי גובה × 5 ערכי גובה פנוי (4000 הרצות), כולם עם seed קבוע ובמודל גבהים דטרמיניסטי; כל המספרים שוחזרו בהרצה חוזרת. אינווריאנטים שנבדקו ועברו: אין אובדן/שכפול/שינוי סדר של טקסט; אין שורה בודדת בשום צד של חיתוך כשהכללים דולקים; אין כותרת בתחתית הטור הימני; הפער בין הטורים שווה למינימום האפשרי לפי חישוב עצמאי; וחלוקה שנכנסת בגובה נבחרת תמיד כשהיא קיימת. **[U]**: כל זה במודל גבהים. עם גבהי שורה אמיתיים, הערות שוליים ועיטורים — לא נבדק.

### 2.6 מניעת שורות וכותרות יתומות/אלמנות (Orphan & Widow Control)

**מינוח.** בקוד ובממשק: **widow** = שורה בודדת שנשארת בתחתית הטור או העמוד; **orphan** = שורה בודדת שעוברת לטור או לעמוד הבא. זה **הפוך** מהמינוח ההדפסתי הרווח בחלק מהמקורות. הוחלט לא לשנות, כי הקוד והממשק עקביים זה עם זה; חייבים רק להישמר בו. מתג נפרד לכל כלל: `avoid-widows` ו-`avoid-orphans` (ברירת מחדל: דלוקים).

**שלוש שכבות** שפועלות יחד:

**שכבה 1: `balanceColumns`, סינון נקודות חיתוך.** חיתוך בתוך פסקה ב-`l` שורות מותר רק אם: לא (`avoidWidows` ו-`l = 1`) ולא (`avoidOrphans` ו-`L − l = 1`). תוצאה: כשהכללים דולקים, פסקה בת 2 או 3 שורות לא נחתכת לעולם.

**שכבה 2: `decideParagraphCut`, החלטה בסוף עמוד/טור** (מקור אחד לשני נתיבי המילוי: טור יחיד ושני טורים). נתונים: `N` שורות בפסקה, `F` שורות שנכנסות בפועל, `pageHasContent`.

```
minStay  = avoidWidows  ? 2 : 1       // מינימום שורות שנשארות כאן
minCarry = avoidOrphans ? 2 : 1       // מינימום שורות שעוברות
F ≥ N                  → הכל נכנס
F ≤ 0                  → pageHasContent ? דחיית כל הפסקה : כפיית שורה אחת
k = F
אם N − k < minCarry    → k = N − minCarry          // קודם מעבירים מספיק שורות הלאה
אם k < minStay         → pageHasContent ? דחיית כל הפסקה : k = F   // ובראש עמוד אי אפשר לדחות
```

**הסדר הוא החלטה מהותית.** הגרסה הקודמת תיקנה "שורה בודדת עוברת" ע"י הקטנת `k`, **ללא בדיקה חוזרת** של כלל השורה הבודדת בתחתית. פסקה בת 3 שורות ש-2 מהן נכנסות הניבה `k = 1`: שורה בודדת בתחתית, בניגוד לכלל. ראו כשל F15.

**כשדוחים את כל הפסקה**, כל כותרת `inline` שנשארה מעליה בסוף הטור נמחקת ונדחית איתה (`stripTrailingHeadings`, `tokenIndex` מופחת בהתאם). הכותרת חייבת להישאר צמודה לטקסט שאחריה.

**שכבה 3: כותרות.**

| מצב | מנגנון |
|---|---|
| `span_1col` | `nextTokPeek`: אם הטוקן הבא פסקה, נדרש `remPageHeight − spanHeight − reserved ≥ minBodyLines × approxLineHeightPx + 15`. `approxLineHeightPx = bodySizePt × 1.333 × lineHeightMult`. `minBodyLines = avoidWidows ? 2 : 1`. אחרת הכותרת נמחקת והעמוד נסגר. |
| `inline_2col` בלולאת המילוי | `stripTrailingHeadings` כשהפסקה שאחריה נדחית או כשאפילו שורה לא נכנסת. |
| `inline_2col` בתוך `balanceColumns` | אין חיתוך מיד אחרי כותרת. |

**למה `minBodyLines = 2` ולא 1:** כלל האלמנות דורש לפחות שתי שורות בתחתית. אם הכותרת שמורה במקום לשורה אחת בלבד, הפסקה שאחריה תיכנס בשורה אחת, תידחה ע"י כלל האלמנות, והכותרת תישאר בודדה. זו בדיוק התקלה שהבדיקה הראשונה שלי לא תפסה. **[R]**

**מגבלות פתוחות [R]:** (א) שרשרת כותרות (`h` ואחריה `h` ואחריה `p`): הבדיקה מסתכלת רק על הטוקן הבא. (ב) `approxLineHeightPx` מוערך, לא נמדד; הקירוב עלול להיות שגוי כשיש מילה ראשונה גדולה. (ג) הדרישה שמרנית: פסקה קצרה מ-`minBodyLines` שורות עלולה לגרום לדחיית כותרת שהייתה נכנסת.

**אימות [E]:** `decideParagraphCut` נטענה מ-`typesetter.js` עצמו (`vm`) ונבדקה על 952 צירופים (`N` 1–14, `F` 0–N, `pageHasContent`, שני הדגלים) מול 7 אינווריאנטים: לא מציבים יותר ממה שנכנס (פרט לכפיית שורה אחת בראש עמוד), הכל נכנס ← הכל מוצב, אין דחייה בראש עמוד, התקדמות מובטחת, **אין שורה בודדת בשום צד כשיש תוכן בעמוד**, אין דחייה מיותרת. 0 כשלים. הקוד הישן, על אותם צירופים: הפרה אחת, פסקה בת 3 שורות ו-2 נכנסות.

### 2.7 כותרות צד והערות צד (Side Headings / Marginalia)

**מקור.** כותרת במצב `side_note` (ברירת מחדל: כותרת 7; אופציונלית 5 ו-6) וסגנון טקסט מיובא עם `layoutMode: side_note`. הטקסט אינו נעשה טוקן עצמאי אלא מוצמד לפסקה הבאה (`sideNote`).

**רינדור.** כשפסקה עם `sideNote` מונחת בטור **ורק אם זה החלק הראשון שלה** (`!isContinuation`), נוצר `div.side-note-anchor` ומצורף ל-`targetMargin`, עמודת השוליים של אותו טור (`rMargin` לטור הימני, `lMargin` לשמאלי). הפסקה מקבלת `data-side-note`, והאלמנט נרשם ב-`pagePendingNotes` (בתוך `balanceColumns`: ב-`finalNotes`) עבור `finalizeNotePositions`. סגנון מיובא מוחל ב-`applyExtStyleToNode`. האלמנט `position: absolute; width: 100%` ורוחבו כרוחב עמודת השוליים (`--w-margin` ≈ 7.5%). **[R]**

**מיקום (`finalizeNotePositions(notesList, columnBoundaryHeight)`).** מקבצים את ההערות לפי עמודת השוליים (`item.elem.parentElement`), וממיינים כל קבוצה לפי `offsetTop` של הפסקה. לכל הערה: `top = pElem.offsetTop`. **רק אם** `top + noteHeight > columnBoundaryHeight`: מחשבים `raisedTop = columnBoundaryHeight − noteHeight` ו-`minTop = prevBottom + 6` (תחתית ההערה הקודמת בקבוצה). אם `raisedTop ≥ minTop` — ההערה מוגבהת ל-`raisedTop`. אחרת מנסים להעביר אותה לשוליים של פסקת ההמשך: `document.querySelector('p[data-token-id="…"][data-is-cont="true"]')`, ואם נמצאה ו-`contTop ≤ maxTop` — ההערה מועברת (`destMargin.appendChild`) ומוצבת ב-`contTop`. אחרת נשארת במקומה וחתוכה. הקוד המלא בסעיף 4.

**השערה [R], לא הוכחה בהרצה:** החיפוש של פסקת ההמשך הוא `document.querySelector` גלובלי, ו-`finalizeNotePositions` נקראת בזמן הבנייה של הבלוק. בשלב זה העמוד הבא, שמכיל את פסקת ההמשך של הפסקה הנוכחית, בדרך כלל עדיין לא נבנה, ולכן `contElem` יהיה `null` וענף ההעברה לא יפעל. אם ההשערה נכונה, הערת צד שאינה נכנסת אפילו לאחר הגבהה נחתכת.

**מגבלה ידועה ב-`finalizeNotePositions` [R]:** בדיקת ההתנגשות בין **הערה להערה** מתבצעת **רק** בענף הגלישה מתחתית הטור (`prevBottom` משמש רק שם). שתי הערות סמוכות שאף אחת מהן לא חורגת מהתחתית יכולות לחפוף זו לזו אם הפסקאות שלהן קרובות אנכית: אין `top = max(top, prevBottom + 6)` כללי. לא שוחזר בהרצה. תיקון מוצע: `top = Math.max(top, prevBottom + 6)` לפני בדיקת התחתית.

**אחרי חיתוך פסקה.** ההערה שייכת לחלק הראשון בלבד. ב-`balanceColumns` היא נוצרת מחדש בתנאי `item.sideNote && !isCont && margin` ולכן עוברת עם תחילת הפסקה: אם האיזון העביר את תחילת הפסקה לטור השמאלי, ההערה תופיע בשוליים השמאליים. ממוקמת אחרי הרינדור הסופי (`finalizeNotePositions`). **[R]**

### 2.8 מנגנון הערות השוליים (Footnotes Positioning)

**תחביר.** טקסט בין תוחמים (`fn-delim-open`/`fn-delim-close`, ברירת מחדל `[` ו-`]`) הופך להערת שוליים; בתוחמים נפרדים להערת סיום. סגנונות טקסט מיובאים (`importedTextStyles`) יכולים להגדיר `target` (`footnote`/`endnote`/`style`) ו-`noteConfig` משלהם. אין אזהרה על תוחם פותח בלי סוגר: הטקסט נשאר גולמי בגוף הפסקה. **[R]**

**מבני נתונים:**

| שם | מבנה | מחזור חיים |
|---|---|---|
| `noteCounters` | `{footnote: n, endnote: n}` | מאופס בתחילת `performTypeset`; משוחזר מ-`snapshot` ב-`balanceColumns` |
| `noteUidCounter` | מספר | מזהה ייחודי `n<k>` לקישור `href="#note-nK"` |
| `footnoteQueueForPage` | `[{number, text, styleId, uid}]` | הערות הממתינות לעמוד הנוכחי; מתרוקן ב-`flushFootnotesInto` |
| `endnoteQueueForPart` | כנ"ל | הערות סיום של החלק; מתרוקן בסוף החלק |

**זרימה:**

1. **יצירת מרקר** (`createNoteMarkerAndQueue`): מגדילה את המונה, מעצבת מספר (`formatNoteMarker`), יוצרת `<a class="note-marker" href="#note-nK">`, ודוחפת `{number, text, styleId, uid}` לתור המתאים.
2. **מספור** (`formatNoteMarker`): `decimal` → `1`; `gematria_geresh` → גימטריה עם גרש; `asterisks` → `*` עד עשרה; `parens` → גימטריה בסוגריים; ברירת מחדל גימטריה. סגנון מיובא יכול לעקוף.
3. **איפוס מונים** (`resetNoteCounterIfNeeded(target, trigger)`): מצב `fn-reset-mode` ∈ {`continuous`, `page`, `part`}. הערות סיום מאופסות תמיד בגבול חלק. סגנון מיובא יכול לקבוע `resetAt`.
4. **הקצאת מקום בזמן המילוי** (`getFootnotesReservedHeight`): `measureNoteBlockHeight(queue, cols) + 24 + (כותרת הערות ? 24 : 0)`. התור הנוכחי בלבד, לכן **הערות הפסקה הנמדדת עצמה** מטופלות בנפרד ע"י `pendingFnMatches` (סעיף 2.4).
5. **מדידה** (`measureNoteBlockHeight`): בונה את בלוק ההערות האמיתי (`buildNoteBlockElement`), מציב `position:absolute; visibility:hidden`, רוחב `calc(180mm × (100 − 2·(w-margin + w-gap))/100)`, מצרף ל-`body`, קורא `offsetHeight`, ומסיר. **הנחה קשיחה: 180mm** — רוחב שטח התוכן של A4 עם שוליים 15mm. שינוי גודל עמוד או שוליים משבש את המדידה. **[R]**
6. **הוספה לעמוד** (`flushFootnotesInto(pageEl)`): נקראת בתחילת העמוד הבא על העמוד שנסגר. בונה `div.footnote-area` (כותרת הערות אופציונלית עם עיטורי צד, קו מפריד `buildNoteRuleElement`, בלוק הערות בעמודות `fn-columns`), ומכניסה אותו ל-`.page-content-wrapper` **לפני** `.page-number-footer`. CSS: `.footnote-area` ברוחב `100% − 2·(w-margin + w-gap)`, `flex-shrink: 0`, כך שהוא תופס מקום ודוחס את גוף העמוד.
7. **הערות סיום** (`flushEndnotesForPart(container, pIdx)`): נצברות ב-`endnoteQueueForPart` ומוצגות בסוף החלק בעמודי `.a4-page` ייעודיים שנוצרים ידנית (לא דרך `createPageLayout`): **אין להם כותרת עליונה ואין אלמנט מספר עמוד**. כותרת העמוד: "הערות", ובעמודי המשך "הערות (המשך)". מספר ההערות בעמוד נקבע ע"י הוספה הדרגתית של הערה והמדידה `wrap.scrollHeight > page.clientHeight − 60`, תוך הבטחת הערה אחת לפחות בעמוד (`i > 0`). כל איטרציה בונה מחדש את הבלוק מ-`i + 1` הערות, כלומר **O(n²)**. תקרה של 200 עמודים. עמודות לפי `cfg.columns` (`column-count: 2`). הערה בודדת גבוהה מעמוד נשארת לבד בעמוד וחתוכה. **[R]**

**שמירה על דטרמיניזם ב-`balanceColumns`.** האיזון מרנדר את אותו תוכן עשרות פעמים. לכן `snapshot` שנשמר בתחילת הבלוק (`blockNoteSnapshot`: אורך התורים, מונים, `noteUidCounter`) משוחזר בתחילת האיזון, וההערכות רצות במצב "יבש" (ללא הכנסה לתור). רק הרינדור הסופי מכניס הערות. בלי זה, כל הערכה הייתה מגדילה את המונים ומשכפלת הערות בתור. **[E]** מכוסה חלקית: ב-2000 תרחישי `balanceColumns` לא נבדקו הערות (מודל ללא תוחמים). **[U]** שמירת ההערות תחת איזון בפועל.

### 2.9 גלישת טקסט בין הטורים ולאזור הערות השוליים (Overflow Handling)

**מה מונע גלישה, שכבה אחר שכבה:**

| שכבה | מנגנון | מצב |
|---|---|---|
| מילוי טור | כל שורה נבדקת: `scrollHeight ≤ availH` (טור יחיד) או `offsetTop + offsetHeight ≤ cachedAvailH` (שני טורים), כש-`availH = remPageHeight − getFootnotesReservedHeight()` | **[R]** |
| הערות הפסקה עצמה | `pendingFnMatches` מחשב מראש בלוק הערות היפותטי ומוריד את גובהו מ-`availH` לפי השורות הנכללות. **בנתיב שני הטורים בלבד** | **[R]** |
| איזון | `heightPenalty = 2000 × חריגה`: חלוקה שגולשת נבחרת רק כשאין אחרת | **[E]** (מודל גבהים) |
| שערי עמוד | `while ((remPageHeight − reserved) > 45)`: אין מתחילים בלוק חדש כשנותרו פחות מ-45px | **[R]** |
| `overflow: hidden` על `.a4-page` | **לא מניעה, אלא הסתרה**: מה שחורג נחתך בשקט | **[R]** |

**פערים מתועדים (לא פתורים):**

1. **מפריד סיום הפרק נוסף בלי בדיקת גובה.** אחרי `balanceColumns` בסוף חלק, `getSectionDividerHTML` מצורף ל-`bodyFlow` ללא בדיקה שיש מקום וללא הפחתה מ-`remPageHeight`. אם העמוד כמעט מלא, המפריד (גובה ברירת מחדל 28px + שוליים 16+6) חורג וייחתך. הקצאת ההערות נמדדה לפני הוספתו. **[R]** זה בדיוק אחד ממקורות התלונה "תוספת גובה הנובעת מעיטורים אינה מחושבת".
2. **התאמת עיטורים אחרי העימוד** (`applyHeadingOrnamentTextFit`) משנה גבהים ורוחבים אחרי שהעמודים כבר נבנו (סעיף 2.12). **[R]**
3. **הערה גבוהה מעמוד שלם.** אין פיצול הערה בין עמודים. עמוד פתיחה ריק מהערות: פסקה אחת עם הערה עצומה → `availH` שלילי → `bestFitLine = 0` → כפיית שורה אחת (`pageHasContent` שקר) → ההערה נדחסת ל-`footnote-area` וחתוכה ע"י `overflow: hidden`. **[R]** לא שוחזר.
4. **רוחב מדידת ההערות 180mm** קשיח (סעיף 2.8). **[R]**
5. **הערת צד שאינה נכנסת.** `finalizeNotePositions` מגביהה אותה, או מנסה להעביר לשוליים של פסקת ההמשך. אם שני אלה נכשלים — נחתכת בשקט. בנוסף: **אין בדיקת חפיפה בין הערות סמוכות מחוץ לענף החריגה מהתחתית** (סעיף 2.7). **[R]**

### 2.10 איזון סוף פרק / סוף חלק (Chapter Balancing)

**הגדרת "פרק".** `sections` נבנה בסריקת הטוקנים: כל כותרת במצב `new_page_1col` או `new_page_2col` (ברירת מחדל: כותרת 2 = סימן) פותחת `section` חדש; כותרת 1 במצב `sub_shaar` יוצרת `section` מסוג שער משנה. לכן **"סוף פרק" = סוף כל סימן** (בהגדרות ברירת המחדל).

**מה קורה בסוף סימן** (תנאי 1 בטבלת סעיף 2.5): `balanceColumns(block2Col, colWidth, styleObj, blockNoteSnapshot, actualAvailH)` מאזנת את הבלוק האחרון, ואחריה `getSectionDividerHTML(secDivStyle)` מצורף. כלומר העמוד האחרון של כל סימן נראה כשני טורים מאוזנים ולא כטור ימני מלא ושמאלי ריק.

**ממצאים:**

- הבורר `balance-chapter-end` קיים ב-`index.html` אך **אין קוד שקורא אותו**. האיזון בסוף פרק פועל תמיד. **[R]** (`grep` בכל הקבצים.)
- הפונקציה `estimateSectionFillRatio(tokens)` מוגדרת ו**אינה נקראת מאף מקום**. מיועדת להערכת מילוי אחרון כדי להחליט אם לאזן. קוד מת. **[R]**
- עמוד אחרון של סימן שהוא מלא כמעט עד הסוף: האיזון פועל ללא תועלת מעשית, וה-`divider` נוסף מעבר לתקציב (פער 1 לעיל).

### 2.11 כותרות עליונות ומספור עמודים

**מבנה.** `createPageLayout(container, h2Text, h2TokenId, pNum, h1Title, h2Title, h3Title, bookTitle, customR, customC, customL, pageRole, pageContext)` יוצרת `.a4-page` עם: כותרת עליונה בת שלוש עמדות (`r`, `c`, `l`), `.page-content-wrapper` שמכיל את גוף העמוד, ו-`.page-number-footer`. רוחב העמדות: `flex: 0 0 var(--hdr-w-*)`. הערך `justify-content: space-between` לא שימש כי הוא אינו ממרכז את העמדה האמצעית כשתוכן העמדות שונה (ראו F8).

**תוכן עמדה** (`renderHeaderSectionHTML(type, customText, h1Title, h2Title, h3Title, bookTitle, tocFallback, contextExtra)`): `h1`, `book_title`, `book_title_split_r`/`_l`, `siman_alone`, `h2_with_siman`, `h2_without_siman`, `h2`, `h3`, `h4`, `page_number`, `first_word_last_word`, `custom`, עיטורי כותרת (`diamonds`, `spear`, `swash`, `pen`, ועיטורי JSON), `empty`.

**עמוד זוגי שונה מאי-זוגי** (`hdr-distinct-even-odd`; `isDistinct`): כשהמתג דלוק ו-`isEven`, כל שדה (סוג, יישור, גופן, גודל, טקסט מותאם) נלקח מבורר ה-`verso` המתאים. ערך `same_as_odd` בבורר של עמוד זוגי (או `same_as_even` בבורר של אי-זוגי) יורש את הצד השני. ההחלפה נעשית **לפני** חישוב היישור. הקוד המלא בסעיף 4.

**יישור `outer`/`inner`** (`resolveHeaderAlign(align, slot)`): `outer` בעמדה `r` = ימין, בעמדה `l` = שמאל; `inner` הפוך. **הפונקציה אינה תלויה בזוגיות העמוד.** "חיצוני" הוא ביחס למיקום העמדה בדף, לא ביחס לשדרת הספר. כדי לקבל חיצוני אמיתי בעמוד זוגי, יש להגדיר את בורר ה-`verso` בהתאם. **[R]**

**קו הפרדה כותרת-גוף.** `hdr-divider-style` ∈ {`none`, `gray`, `black`}; ה-JS קובע `--hdr-divider-color`; ה-CSS: `border-bottom: 1px solid var(--hdr-divider-color, rgba(0,0,0,.06))`. **[R]**

**מספור עמודים** (`formatPageNumberDisplay(pNum)`): נקרא מכל נקודת רינדור עמוד.

```
effectiveNum = pNum − startIdx + initialValue          (רק אם pNum ≥ startIdx)
פורמט: gematria | page_gematria ("דף " + גימטריה) | numeric
מסגרת: page-num-frame-<סוג> על <span class="page-num-badge">
מיקום: bottom_center | bottom_outer (ב-.page-number-footer) | אחר (בכותרת / ללא)
```

**ספירה לעומת הצגה: מצב חלקי.** הבקרות בקובץ הנוכחי (נקראו מ-`index.html` ו-`typesetter.js`):

| בקרה | ברירת מחדל | משפיעה על |
|---|---|---|
| `main-shaar-count-numbering` | כבוי | האם שער ראשי מקדם את `pageIndex` |
| `back-shaar-count-numbering` | כבוי | שער אחורי |
| `sub-shaar-count-numbering` | דלוק | שער משנה |
| `general-toc-count-numbering` | דלוק | תוכן עניינים כללי: נספר |
| `detailed-toc-count-numbering` | דלוק | תוכן עניינים מפורט: נספר |

**אין בקרת `show-numbering` לשערים** (`main/sub/back-shaar-show-numbering`: 0 הופעות בקבצים הנוכחיים). הכוונה "לכלול במיספור בלי להציג" מקוימת **רק לתוכן עניינים**; בשערים אפשר רק לבחור אם הם נספרים. הבקרות לשערים נבנו בשיחה (יחד עם העברת `pageIndex` לפונקציות הרינדור של השערים) ואבדו במיזוג. **[E]** (`grep`) `page-num-initial-value` היה רק בגרסה הישנה ביותר והוחזר במיזוג.

### 2.12 עיטורים: מערכת הגדלים והתאמת רוחב לטקסט

**רישום נכסים** (`decorations.js`): `HEADER_ORNAMENTS`, `SECTION_DIVIDERS`, `ORNAMENTS_UD` (עליון/תחתון), `ORNAMENTS_LR` (צד, עם מראה), `EXTERNAL_ALL_ORNAMENTS` (נטענים מ-JSON או תיקייה), `EXTERNAL_SHAAR_ASSETS`. כל אחד הוא `מזהה → מחרוזת SVG/HTML`.

**בקרת גודל.** שדות `dim-*` (רוחב וגובה כמחרוזת CSS חופשית): `dim-hdr-w/h`, `dim-secdiv-w/h`, `dim-h2-top-w/h`, `dim-h2-btm-w/h`, `dim-h2-title-side-w/h`, `dim-h3-side-w/h`, `dim-note-side-w/h`. המחוללים מזריקים את הגודל כ-`style` מוטבע על ה-SVG עם `!important`.

**הטכניקה `svgNoStyle`.** כדי שגודל מהלוח יחול על SVG מובנה, מסירים קודם את ה-`style="..."` הקשיח שכבר קיים על תג ה-`<svg>` (`/<svg[^>]*style="[^"]*"/` ← `<svg`), ורק אז מזריקים `<svg style="width…!important; height…!important;" `. בלי הסרה נוצרים שני מאפייני `style` וה-HTML מתעלם מהשני. `!important` נדרש כי ב-CSS קיימים כללי גודל (מבוססי `em`) עם `!important` שגוברים על `style` מוטבע רגיל. **[R]**

**תנאי ה-bug שחזר פעמיים:** `dimStyle` חושב אך הוחל רק על `custom_img`, לא על עיטורים מובנים ולא על עיטורי JSON (F11).

**התאמת רוחב עיטור כותרת 2 לרוחב הטקסט: עקרונית שבורה בקוד הנוכחי.**

```
applyHeadingOrnamentTextFit()      // app.js, נקראת בסוף performTypeset
   לכל עיטור עליון/תחתון של כותרת 2:
       textWidth = sibling.offsetWidth
       ornament.style.width = textWidth + 'px'
```

`sibling` הוא `.title-level-2-standalone` שה-CSS שלו הוא `width: 100%; text-align: center`. אלמנט בלוק ברוחב מלא: `offsetWidth` שלו הוא **רוחב המכולה**, לא רוחב הטקסט. לכן העיטור תמיד מקבל רוחב מלא (מוגבל ע"י `max-width: 90%`), והתאמה לטקסט **לא מתרחשת לעולם**. **[R]** (מבוסס על קריאת ה-CSS; לא ניתן להריץ בלי layout.) לפחות שתי גישות נכשלו מאותה סיבה: ראו F11. התיקון הנכון:

```js
// מדידת רוחב טקסט אמיתי, לא רוחב אלמנט בלוק
const range = document.createRange();
range.selectNodeContents(titleEl);
const textWidth = range.getBoundingClientRect().width;
```

וחובה להריץ את ההתאמה **לפני** מדידת גובה הבלוק בלולאת העימוד, לא כשלב אחרי.

**התאמת גובה עיטור צד לטקסט (כותרת 3).** גם היא ב-`applyHeadingOrnamentTextFit` (אחרי העימוד): `ornament.style.height = .h3-title-text.offsetHeight`. כאן המדידה תקינה (אלמנט שורה), אך היא משנה גובה אחרי שה-`spanBlock` כבר נמדד ונוכה מהתקציב. אם גובה העיטור לפני ההתאמה שונה מזה שאחריה, תקציב העמוד שגוי באותו הפרש. **[R]**

### 2.13 שערים וערכות נושא

- **סוגים:** שער ראשי, שער אחורי, שער משנה (לכל חלק). רינדור: `renderMainShaar(container, themeId, pageIndex)`, `renderBackShaar(...)`, `renderSubShaar(container, token, themeId, pageIndex)`.
- **תבנית שער = SVG + תיבת טקסט.** תיבת הטקסט מוגדרת במ"מ (`builder-{main|back|sub}-{top|bottom|right|left}`). עורך בעכבר (`initShaarBoxResizer`) גורר ומשנה גודל ומעדכן את אותם שדות.
- **שמירת מיקום תיבה לכל שער** (`window.shaarBoxSavedPositions[type][id]`): נשמר ב-`window`, מוטמע בתבנית שמיוצאת (`saveAsDefaultTemplate`), משוחזר בטעינה, ומוחל בבחירת השער. שערי JSON נושאים `box` משלהם; `exportShaarJSONWithPositions(type)` מייצא `[{id, name, svg, box}]` כאשר מיקום שמור גובר על `item.box`. זו המימוש העדיף על מנגנון `localStorage` שנבנה קודם בשיחה, כי הנתון נשאר עם הקובץ. **[R]**
- **איחוד ערכות לפי מספר:** קובצי `shaar_*.json` עם אותו מספר מצורפים לערכה אחת (`jsonShaarSets`). תיקון שנבנה בשיחה (`anchoredMatch`: להעדיף מספר בתחילת המזהה ולא כל ספרה בשם, כדי לא לשייך `shaar_main_2_v10` לערכה 10) **אינו קיים בקוד הנוכחי** (0 הופעות). התנהגות החילוץ הנוכחי לא נבדקה. **[E]** (`grep`)
- **שער ראשי ברירת מחדל:** `BUILTIN_SHAAR_THEMES`; כשערכה נבחרת אך אין בה סוג מסוים — מופל `theme_default`.
- **גב השער: חסר בקוד הנוכחי.** נבנו בשיחה שלוש תיבות טקסט עצמאיות (`inp-back-copyright`, `inp-back-info-box`, `inp-back-footer`) עם נפילה לברירת מחדל. בקבצים הנוכחיים יש **0 הופעות** שלהן: הן אבדו במיזוג. `renderBackShaar` משתמש שוב בטקסט זכויות קשיח ובשדות השער הראשי. **[E]** (`grep`). ראו סעיף 6.

### 2.14 ביצועים ותצוגה מקדימה

- **הפעלה מבוקרת** (סעיף 1.7): ההגדרות נאספות; עימוד מלא רק בלחיצה.
- **סינכרוניות:** העימוד מבצע מדידות DOM רבות: אחת לכל שורה בכל פסקה בלולאת ההתאמה, ועשרות עד מאות הערכות לכל איזון בלוק. זמן הריצה לא נמדד בדפדפן אמיתי. **[U]**
- **תצוגה מקדימה (`updatePreviewScale`):** `#book-container` מקבל `transform: scale(var(--preview-scale)); transform-origin: top center`, ובסעיף 3 מתועדת תקלת טשטוש שנגרמת מ-`transform: scale` על טקסט. **תיקון שנבנה בשיחה** (`zoom` במצב מנוחה ו-`transform` רק בזמן שינוי גודל, מחלקת `.is-scaling`) **אינו קיים בקוד הנוכחי**; הוא אבד במיזוג. **[R]**

### 2.15 טעינת נכסים ותיקיות

**שני מנגנונים קיימים במקביל:**

1. **`loadExternalJSONAssets()`**: `fetch` של קובצי JSON קבועים. נכשל ב-`file://` ב-Chrome.
2. **`loadFolderAssetsAndThemes()`**: `fetch('assets_manifest.json')` — מניפסט שצריך להכין מראש.
3. **`handleAssetsFolderSelected(event)`** (נבנה בשיחה): `<input type="file" webkitdirectory>`. הדפדפן **אינו מסוגל** לסרוק תיקייה מקומית ביוזמתו; כל גישה דורשת בחירה מפורשת. אחרי בחירה אחת, הזיהוי אוטומטי לפי שם תת-התיקייה: `section_dividers`, `header_ornaments`, `ornaments_up_down`, `ornaments_left_right`, `note_rules`, `shaar_main`/`shaar_sub`/`shaar_back`, ו-`THEMES/<שם ערכה>/` (קבצים בתוכה מזוהים לפי שם: `main`/`ראשי`, `sub`/`משנה`, `back`/`אחורי`). פורמטים: SVG (נטען כטקסט כדי שירש צבע וגודל), PNG, JPG, GIF, WEBP (כ-`<img src="data:…">`).

**למה `webkitdirectory` ולא `showDirectoryPicker`:** `showDirectoryPicker` נתמך רק ב-Chrome ו-Edge. ל-Firefox ו-Safari הוא לא נחשף, מטעמי אבטחה. `webkitdirectory` נתמך בכל הדפדפנים. **[R]** (נבדק בחיפוש ברשת בשיחה.)

### 2.16 גופנים

- **41 בוררי גופן** (`.font-picker`) ב-`index.html`, ריקים ב-HTML. אכלוס בזמן ריצה: לכל `select` ריק מוכנסות קבוצות `optgroup` מהרשימה הקבועה `defaultFonts`, והערך נקבע לפי המפה `pickerDefaults[select.id]` (ברירת מחדל `'David Libre', serif`). נוספים: גופני מערכת דרך `loadSystemFonts()` (`window.queryLocalFonts()`, Chromium בלבד) וגופנים מהתיקייה `fonts/` דרך `loadExternalFonts()` (`new FontFace(...)` + `document.fonts.add`), כל אחד ב-`optgroup` נפרד.
- **תנאי מקדים למדידה:** `ensureBuiltinFontsLoaded()` טוענת מראש שש משפחות (Assistant, Rubik, Bellefair, David Libre, Frank Ruhl Libre, Noto Serif Hebrew) בשלושה משקלים (400, 700, 900) וממתינה ל-`document.fonts.ready`. העימוד מבוסס מדידה; אם הוא רץ לפני שהגופן נטען, השבירות נמדדות עם גופן חלופי ושגויות אחר כך. **[R]**
- **היסטוריה:** בקו פיתוח קודם (שנבנה בשיחה) הבוררים בקובץ ה-HTML היו ריקים לגמרי, והוספנו אפשרות `David Libre` קשיחה בכל בורר כדי שלא יישארו ריקים. בקוד הנוכחי האכלוס מתבצע ב-JS והמפה `pickerDefaults` מגדירה ברירות מחדל, ולכן אין צורך בהן ב-HTML. **[R]**

### 2.17 ייצוא תבנית והדפסה

- **`saveAsDefaultTemplate()`**: מסנכרנת כל ערך של `input`/`select`/`checkbox` ל-attributes (`value`, `selected`, `checked`) כדי ש-`outerHTML` ישמור אותם; מרוקנת את העורך לפני ההסרה ומשחזרת אחריה (דרך ה-shim של `.value`); מייצאת `'<!DOCTYPE html>\n' + document.documentElement.outerHTML` כקובץ `torani-master-template.html`. ייצוא כקובץ יחיד מחייב הטמעת ה-CSS וה-JS (בגרסה המפוצלת: `fetch` וקריאה מחדש, עם בריחת `</script`; ראו F1).
- **הדפסה:** `@media print` ו-`@page` ב-`style.css`; כל `.a4-page` עם `page-break-after`. הדפסה בפועל דורשת ביטול כותרות עליונות/תחתונות של הדפדפן ושוליים "ללא".

## 3. יומן כישלונות, טעויות וניסיונות שנפסלו (Mistakes & Failed Approaches)

כל רשומה: **הגישה** שהוצעה, **התרחיש** שבו נכשלה, **ההוכחה** (ורמת האימות שלה), **המסקנה** שאסור לשכוח. הרשומות מקובצות לפי סוג. כשהכשל היה טענה שגויה שלי ולא באג בקוד, זה נאמר במפורש: הם חלק מהמידע החשוב ביותר במסמך הזה.

### א. טענות שגויות שהוצגו כממצאים (שגיאות אבחון)

#### F16. "באג קריטי: `#raw-input` הוא div, אין לו `.value`, אף טקסט לא מגיע לעימוד"

- **הגישה:** קריאת `document.getElementById('raw-input')?.value` ב-`typesetter.js` סומנה כבאג הקריטי ביותר בפרויקט, ותוקנה ל-`getCleanEditorText()`. בהמשך אותה טענה שימשה להערכת גרסאות ("גרסה 4 שהדוח ממליץ עליה עדיין סובלת מהבאג הקריטי").
- **התרחיש:** הטענה נשענה על מפרט ה-DOM בלבד: ל-`<div contenteditable>` אין מאפיין `value`. **הקוד מגדיר אותו בעצמו:** `app.js` מכיל `Object.defineProperty(editorElem, 'value', {get: getCleanEditorText, set: renderEditorContent})`. ב-`.value` הקוד עובד.
- **איך התגלה:** כתבתי בדיקות jsdom לשלוש "תקלות נתונים" נלוות (ייבוא `.txt`, שמירת תבנית, טקסט ברירת מחדל). הן עברו 7/7 **גם על הקוד שלפני התיקון**. במקום להתעלם מזה בדקתי למה, וקראתי את `app.js` בחיפוש `defineProperty`.
- **הוכחה:** **[E]** הרצת אותן בדיקות על הקובץ הישן נתנה 7/7. **[E]** `grep defineProperty` מצא את ה-shim.
- **מסקנה:** (1) לפני שמכריזים על באג מבוסס-מפרט, מחפשים `defineProperty` ו-shims בכל הקוד. (2) **בדיקה חדשה חייבת להיכשל על הקוד הישן** — אחרת היא לא בודקת כלום (בדיקת מוטציה). (3) ההכרזות הקודמות ("הבאג החמור ביותר בשיחה") שגויות ובוטלו. התיקון עצמו (`getCleanEditorText()`) תקין אך מיותר.

#### F17. טענות שגויות על דוח ההשוואה ועל "תכונות חסרות"

- **ממצא א:** הדוח טען שמנגנון הערות האטומיות `\uE000` קיים בגרסאות 3 **ו**-4. בדיקה: `מערכת.txt` מכילה **0** מופעים של התו; רק גרסה 4. **[E]** הדוח שגוי בנקודה זו.
- **ממצא ב:** סימנתי "כותרות עצמאיות לעמוד זוגי חסרות" כי חיפשתי את השמות **שלי** (`hdr-even-independent`, `hdr-even-r-type`). הפונקציה קיימת בשמות אחרים (`hdr-distinct-even-odd`, `hdr-verso-*`, `isDistinct`) ובמימוש מלא יותר. **[E]** (נקרא ישירות.)
- **ממצא ג:** `grep` על `getElementById('raw-input')?.value` "מצא" את הבאג גם בקובץ שבו הביטוי הוא רק fallback בתוך `getCleanEditorText ? getCleanEditorText() : (…?.value)`. התאמת מחרוזת אינה הוכחת תקלה.
- **מסקנה:** בדיקת נוכחות תכונה בין גרסאות חייבת לחפש **סמנים סמנטיים** (מה שהקוד עושה), לא את השמות שאני נתתי. וצריך לקרוא את ההקשר של כל התאמה.

#### F27. "תיקון 5": הוספת `oninput="typesetDocument()"` ל-17 שדות ממדים בקובץ המשולב 2

- **הגישה:** בקובץ המשולב הראשון לא נמצא מאזין מרכזי (`grep addEventListener` החזיר מאזין יחיד, של העורך), ולכן שדות `.dim-box` נראו ללא טיפול. שיחזרתי את אותו "תיקון" גם ל-v2, כ"פער רחב שחזר".

פונקציה טהורה, בלי DOM, ולכן ניתנת לבדיקה ממצה. טיפול בשגיאות: קלטים מובנים בלבד; `fitLines ≤ 0` ו-`fitLines ≥ totalLines` מטופלים במפורש; בראש עמוד (`pageHasContent` שקר) לעולם לא מוחזר `pushWhole`, כדי שהעמוד לא יישאר ריק ולא תיווצר לולאה אינסופית. מקרה קצה: `totalLines < 1` אינו מטופל (הקוראים לא מעבירים אותו).

```javascript
// typesetter.js:373-385
function decideParagraphCut(totalLines, fitLines, pageHasContent, avoidWidows, avoidOrphans) {
    if (fitLines >= totalLines) return { count: totalLines, pushWhole: false };
    if (fitLines <= 0) return pageHasContent ? { count: 0, pushWhole: true } : { count: 1, pushWhole: false };
    const minStay = avoidWidows ? 2 : 1;
    const minCarry = avoidOrphans ? 2 : 1;
    let k = fitLines;
    if (totalLines - k < minCarry) k = totalLines - minCarry;     // להעביר מספיק שורות הלאה
    if (k < minStay) {                                            // ולוודא שנשארות מספיק שורות כאן
        if (pageHasContent) return { count: 0, pushWhole: true };
        k = fitLines;      // ראש עמוד: אי אפשר לדחות. עדיף שורה בודדת אחת מעבר מאשר עמוד חסר
    }
    return { count: k, pushWhole: false };
}
```

### 4.4 טיפול בשגיאות: תבניות בקוד

- **הגנה על DOM חסר:** `?.`, `|| ברירת מחדל`, `typeof fn === 'function'` לפני קריאה לפונקציה אופציונלית. רוב הפקדים נקראים כך. פקד שנמחק מה-HTML פשוט מחזיר ברירת מחדל, **בשקט**.
- **`try/catch`:** נדיר. דוגמאות: `new RegExp(def.parseRegex)` מסגנון מיובא; טעינת גופנים וקבצי JSON. ה-`catch` ריק ולכן כשלים אינם מדווחים.
- **אין גבול שגיאה גלובלי** סביב `performTypeset`. חריגה באמצע משאירה DOM חלקי (המכל מנוקה בתחילת הריצה). **[R]**
- **הגנות לולאה אינסופית:** `pagesUsed > 200` בעמודי הערות סיום; שאר הלולאות מסתמכות על כך שכל עמוד מציב לפחות שורה אחת (`decideParagraphCut` מבטיח).
- **שגיאות קלט משתמש:** תוחם פותח בלי סוגר ← טקסט גולמי; כותרת עם מספר רמה לא קיימת ← פסקה רגילה (אין בדיקה אקטיבית). **[R]**

### 7.2 `verify_cut.js`: בדיקה ממצה של `decideParagraphCut`

טוענת את הפונקציות **מהקובץ עצמו** (לא עותק) דרך `vm`. 952 צירופים × 7 אינווריאנטים.

```javascript
// verify_cut.js
// טוענים את הפונקציות האמיתיות מתוך typesetter.js עצמו (לא עותק) ובודקים אותן.
// שימוש: node verify_cut.js [נתיב ל-typesetter.js]
const fs = require('fs'), vm = require('vm');
const src = fs.readFileSync(process.argv[2] || 'typesetter.js', 'utf8');
const grab = name => { const m = src.match(new RegExp('^function ' + name + '\\([\\s\\S]*?^\\}\\n', 'm')); if (!m) throw new Error(name + ' not found'); return m[0]; };
const ctx = {}; vm.createContext(ctx);
vm.runInContext(grab('decideParagraphCut') + '\n' + grab('stripTrailingHeadings'), ctx);
const { decideParagraphCut } = ctx;

let total = 0, failures = [];
const fail = (msg, a) => failures.push(msg + '  ' + JSON.stringify(a));
for (let N = 1; N <= 14; N++) for (let F = 0; F <= N; F++)
  for (const pc of [true, false]) for (const W of [true, false]) for (const O of [true, false]) {
    total++;
    const a = { N, F, pageHasContent: pc, W, O };
    const r = decideParagraphCut(N, F, pc, W, O);
    // 1. לעולם לא מציבים יותר משנכנס, פרט לכפיית שורה אחת בראש עמוד ריק (כלל מכוון - אחרת העמוד נשאר ריק)
    if (r.count > Math.max(F, pc ? 0 : 1)) fail('הוצבו יותר שורות ממה שנכנס', { ...a, r });
    if (!pc && F === 0 && !(r.count === 1 && !r.pushWhole)) fail('ראש עמוד שבו לא נכנס דבר: חייבת להיכפות שורה אחת', { ...a, r });
    // 2. אם הכול נכנס - מציבים הכול
    if (F >= N && !(r.count === N && !r.pushWhole)) fail('הכול נכנס אך נחתך', { ...a, r });
    // 3. דחיית כל הפסקה אסורה בראש עמוד (אחרת לולאה אינסופית / עמוד ריק)
    if (!pc && r.pushWhole) fail('דחייה בראש עמוד', { ...a, r });
    // 4. מחוץ לדחייה - תמיד מציבים לפחות שורה אחת (התקדמות מובטחת)
    if (!r.pushWhole && r.count < 1) fail('אפס שורות ללא דחייה', { ...a, r });
    // 5. הכלל המרכזי: כשיש תוכן בעמוד - אין שורה בודדת בשום צד של חיתוך
    if (pc && !r.pushWhole && r.count < N) {
      if (W && r.count === 1) fail('widow: שורה בודדת בתחתית', { ...a, r });
      if (O && N - r.count === 1) fail('orphan: שורה בודדת עוברת', { ...a, r });
    }
    // 6. דחייה מותרת רק כשבאמת אי אפשר לחתוך חוקית (לא דוחים סתם)
    if (r.pushWhole && F >= N) fail('דחייה מיותרת', { ...a, r });
  }
console.log('שילובים שנבדקו:', total, '| כשלים:', failures.length);
failures.slice(0, 6).forEach(f => console.log('  ', f));

// דוגמאות קריטיות, מודפסות במפורש
const show = (N, F, W, O) => { const r = decideParagraphCut(N, F, true, W, O); return `N=${N} F=${F} W=${W} O=${O} => ${r.pushWhole ? 'דוחים את כל הפסקה' : 'נשארות ' + r.count + ', עוברות ' + (N - r.count)}`; };
console.log('\nהמקרה שנכשל בקוד הישן:'); console.log('  ' + show(3, 2, true, true));
console.log('מקרים רגילים:'); [[10,7],[5,4],[4,2],[2,1],[6,1]].forEach(([N,F]) => console.log('  ' + show(N, F, true, true)));
console.log('רק widow דלוק:  ' + show(3, 2, true, false) + ' | רק orphan דלוק: ' + show(3, 2, false, true));
process.exit(failures.length ? 1 : 0);
```

### 7.3 `test_balance.js`: הרצת `balanceColumns` האמיתית על תרחישים אקראיים

מודל גבהים דטרמיניסטי: מילה = שורה = 20px, כותרת = 40px. `getLinesFromParagraph` מוחלפת כך שכל מילה היא שורה, ובכך שליטה מלאה במספר השורות. בודקת: שימור טקסט וסדר, אין שורה בודדת כשהכללים דולקים, אין כותרת בתחתית הימנית, אופטימליות מול חישוב עצמאי, ושחלוקה שנכנסת בגובה נבחרת. כוללת **בקרה שלילית** (כללים כבויים ← מצופות הפרות, להוכחה שהגלאים אינם עיוורים).

```javascript
// test_balance.js
// מריץ את balanceColumns האמיתית (מתוך typesetter.js) על תרחישים אקראיים במודל גבהים דטרמיניסטי.
// שימוש: node test_balance.js [נתיב ל-index.html]   (ברירת מחדל: /tmp/bomrun/index.html - עותק עם BOM, ראו סעיף 7.1)

(async () => {
  const dom = await JSDOM.fromFile(htmlPath, { url: "file://" + htmlPath, resources: "usable", runScripts: "dangerously",

  const words = el => (el.textContent || '').replace(/\u00a0/g, ' ').trim().split(/\s+/).filter(Boolean);

    if (el.tagName === 'P') return words(el).length * 20;

    let s = 0; for (const c of el.children) s += H(c); return s;
  };

  Object.defineProperty(window.HTMLElement.prototype, 'offsetHeight', { configurable: true, get() { return H(this); } });

  const setFlags = (W, O) => { document.getElementById('avoid-widows').checked = W; document.getElementById('avoid-orphans').checked = O; };

  function buildScenario(rand) {
    const n = 1 + Math.floor(rand() * 8);
    const items = [];
    for (let i = 0; i < n; i++) {
      if (rand() < 0.3 && i < n - 0) items.push({ type: 'h', id: 'h' + i });
      else items.push({ type: 'p', id: 't' + i, lines: 1 + Math.floor(rand() * 12) });
    }

    return items;
  }
  function render(items) {

    block.innerHTML = '<div class="margin-notes-column right-margin"></div><div></div><div class="main-column right-col"></div><div class="col-gutter-divider"></div><div class="main-column left-col"></div><div></div><div class="margin-notes-column left-margin"></div>';
    const rCol = block.querySelector('.right-col');
    const tokens = [];
    items.forEach(it => {

        const d = document.createElement('div'); d.className = 'title-level-4'; d.setAttribute('data-token-id', it.id); d.textContent = 'H_' + it.id; rCol.appendChild(d); tokens.push('H_' + it.id);
      } else {
        const ws = Array.from({ length: it.lines }, (_, k) => it.id + '_' + (k + 1));
        const p = document.createElement('p'); p.className = 'p-end'; p.setAttribute('data-token-id', it.id); p.setAttribute('data-is-cont', 'false');
        p.setAttribute('data-raw-text', ws.join(' ')); p.textContent = ws.join(' '); rCol.appendChild(p); tokens.push(...ws);
      }
    });
    document.body.appendChild(block);
    return { block, tokens };
  }

  // מונה בלתי-תלוי של כל נקודות החיתוך החוקיות (לפי הכללים המתועדים) - להשוואת אופטימליות
  function legalRightHeights(items, W, O) {
    const lh = it => it.type === 'h' ? 40 : it.lines * 20;
    const total = items.reduce((s, it) => s + lh(it), 0);
    const out = []; let acc = 0;
    for (let i = 0; i <= items.length; i++) {
      const it = items[i];
      if (!(i > 0 && items[i - 1].type === 'h')) out.push(acc);          // אסור חיתוך מיד אחרי כותרת
      if (it && it.type === 'p') for (let l = 1; l < it.lines; l++) { if (W && l === 1) continue; if (O && it.lines - l === 1) continue; out.push(acc + l * 20); }
      if (it) acc += lh(it);
    }
    return { total, out };
  }
  function bestPossibleDiff(items, W, O) {
    const { total, out } = legalRightHeights(items, W, O);
    return Math.min(...out.map(r => Math.abs(r - (total - r))));
  }

      const R = Array.from(block.querySelector('.right-col').children), L = Array.from(block.querySelector('.left-col').children);
      const out = []; [...R, ...L].forEach(el => out.push(...words(el)));
      if (out.length !== tokens.length) { stats.lost++; examples.lost = examples.lost || JSON.stringify({ items, out: out.length, exp: tokens.length }); }
      else if (out.some((t, i) => t !== tokens[i])) { stats.orderBroken++; examples.order = examples.order || JSON.stringify({ items }); }
      // פסקאות שנחתכו בין הטורים
      const idOf = el => el.getAttribute('data-token-id');
      const rIds = new Map(), lIds = new Map();
      R.forEach(el => { if (el.tagName === 'P') rIds.set(idOf(el), (rIds.get(idOf(el)) || 0) + words(el).length); });
      L.forEach(el => { if (el.tagName === 'P') lIds.set(idOf(el), (lIds.get(idOf(el)) || 0) + words(el).length); });
      rIds.forEach((rn, id) => { if (lIds.has(id)) {
        stats.cuts++; const ln = lIds.get(id);
        if (rn === 1) { stats.widow++; examples.widow = examples.widow || JSON.stringify({ items, W, O, right: rn, left: ln }); }
        if (ln === 1) { stats.orphan++; examples.orphan = examples.orphan || JSON.stringify({ items, W, O, right: rn, left: ln }); }
      } });
      const lastR = R[R.length - 1];
      if (lastR && lastR.tagName !== 'P' && L.length > 0) { stats.headingAtBottom++; examples.heading = examples.heading || JSON.stringify({ items }); }
      if (avail === Infinity) {
        const rH = R.reduce((a, el) => a + H(el), 0), lH = L.reduce((a, el) => a + H(el), 0);
        if (Math.abs(rH - lH) !== bestPossibleDiff(items, W, O)) { stats.notOptimal++; examples.opt = examples.opt || JSON.stringify({ items, W, O, got: Math.abs(rH - lH), want: bestPossibleDiff(items, W, O) }); }
      }
      block.remove();
    }
    return { stats, examples };
  }

  // בדיקת גובה: כשקיימת חלוקה חוקית שנכנסת - חייבת להיבחר; אחרת - זו שגולשת הכי פחות
  function runFit(count, seed, W, O) {
    const rand = rng(seed); const s = { runs: 0, mustFitButOverflowed: 0, notLeastOverflow: 0, fitCases: 0, overflowCases: 0 }; let ex = null;
    for (let k = 0; k < count; k++) {
      const items = buildScenario(rand); setFlags(W, O);
      const { total, out } = legalRightHeights(items, W, O);
      const minMax = Math.min(...out.map(r => Math.max(r, total - r)));
      for (const delta of [-60, -20, 0, 20, 100]) {
        const avail = minMax + delta; const { block } = render(items);
        window.balanceColumns(block, 280, { fontFamily: 'serif', fontSize: '11pt', lineHeight: '1.34' }, null, avail);
        const R = Array.from(block.querySelector('.right-col').children), L = Array.from(block.querySelector('.left-col').children);
        const got = Math.max(R.reduce((a, e) => a + H(e), 0), L.reduce((a, e) => a + H(e), 0));
        s.runs++;
        if (delta >= 0) { s.fitCases++; if (got > avail) { s.mustFitButOverflowed++; ex = ex || JSON.stringify({ items, W, O, avail, got, minMax }); } }
        else { s.overflowCases++; if (got !== minMax) { s.notLeastOverflow++; ex = ex || JSON.stringify({ items, W, O, avail, got, minMax }); } }
        block.remove();
      }
    }
    return { stats: s, examples: ex ? { first: ex } : {} };
  }
```
